## 6.5.2. Поиск карточек и страница карточки

Ориентир по жесту — публикатор (как Obsidian Publish): клик по узлу графа
и переход по `[[wikilink]]` открывают **страницу карточки**. На карточке
сбоку — локальный граф этой заметки. Раскладка холста — fCoSE (§6.5.1).
Поиск — по индексу GraphNotes (название, путь, slug, **теги**).
Текущий движок — SQL и **остаётся SQL**, пока не начнётся итерация ES.
Elasticsearch — **следующая итерация** (ADR-015): итерация начинается
**только после первой утверждённой выкатки на production `rhizome`**.
Не сейчас, не эта ветка, не этот Compose.

Карточку на сайте **не правят** (ТЗ **2.93**): нет кнопки «Отредактировать
карточку», нет MDXEditor. Обратной выгрузки склада GraphNotes → vault /
диск пользователя пока нет — править файл в браузере незачем. Редактор
включают, когда появится **обратная загрузка / обратная синхронизация**.
Когда можно будет **взять карточку другого участника себе в ризому**,
для тех карточек — редактура и обратная синхронизация. До тех пор
страница карточки — только просмотр: своя личная, чужой личный
(`personal:{uuid}:…`), общая и правка из очереди. Предложение в общую —
`/offer` (предложения и сверка Differ), не поле на общей карточке.
Писать в личный склад сейчас можно **плагином**. Кнопки загрузки `.md`/ZIP
на сайте нет (ТЗ **2.96**). Когда вернём загрузку — только API в локальный
склад. Git copy-in остаётся коннектором.

- **`/`** по-прежнему «старт = граф» (§5.6): `/` → `/graph`.
- `/card` без пути: UUID или git-путь в настройках инсталляции; пишет
  только `admin`; если не задана — **404**.

In-app правка на сайте **выключена** (ТЗ **2.93**). Класс

ТЗ 2.48–2.53 держали тонкий редактор своей карточки (`PersonalCardEditor` /
MDXEditor после «Отредактировать карточку»). Снято, пока нет обратного пути
склад → пользователь. Компонент в репозитории оставлен; на страницу карточки
не монтируется. `:` в hash как `%3A` по-прежнему свой личный путь, не
«не тот слой».

### Поиск

На холсте `/graph` остаётся поле поиска (подсветка узлов). Отдельный экран
**`/search`** — каталог: крупное поле, теги чипами. Хит ведёт на
`/card/{путь}`. Слой в адресе не пишется; на странице карточки слой не
объясняют.

Архитектура: поиск — не второй каталог, а чтение того же `note_index` с
**предикатом видимости по роли**. Хит несёт слой (`shared` / `personal` /
`proposal`), чтобы UI подсветил, откуда карточка. Слои графа (ваша часть /
ваша личная) остаются фильтром холста; `/search` по умолчанию ищет всё,
что этому зрителю уже можно открыть (`layer=visible`).

| Зритель | Корпус `/search` |
| --- | --- |
| Гость | опубликованная общая |
| `user` | общая **и своя** ризома (полный личный склад: у нас или git) |
| `editor` | своя + общая + **правки, которые дали на ревью** (слой `proposal`) |
| `admin` | все карточки, которые можно открыть: общая, **все** личные слои, очередь правок |

- Подключён личный слой — в выдаче чип **общая / ваша / правка** (цвет слоя,
  не одна подпись на весь список). Можно сузить фасетом.
- Гость ищет по опубликованной общей: совпадения на `/graph` **и** в
  `/search` открывают `/card/{путь}` (тело опубликованной общей). Личное
  и очередь гостю не открываются.
- Вошедший из выдачи переходит на `/card/{путь}`, если есть право.
  Личная чужого user’а в чужой выдаче не светится. Editor видит чужое
  только как правку очереди, не весь чужой vault. Admin открывает чужой
  личный путь `personal:{uuid}:{путь}`.
- Граф по-прежнему не высыпает весь vault: «ваша часть ризомы» — overlay.
  `GET /api/search?layer=overlay` остаётся для подсветки на графе.
- Пустой `/search` не маскирует ризому: видны теги, приглашение набрать слово.
  Нет совпадений — сказано прямо.
- Поиск не подменяет Differ.
- Поиск читает тот же производный `note_index`, что и граф, на **текущих**
  git-деревьях. Предложение при создании проецируется в слой `proposal`
  (не канон Markdown). После публикации эти строки снимаются: карточка уже
  в общей. Пересборка индекса (кнопка, смена SHA, webhook/опрос) одна:
  граф **и** поиск. Удалённый из git путь исчезает из `/search` и из выдачи;
  `/card/{путь}` не изобретает карточку — GET тела отвечает 404.
  Карточка и новый комментарий перед чтением обновляют HEAD git: старый
  SHA не показывает снятый файл. Комментарий к снятому пути —
  «note was not found»; висячие комментарии с пересборки снимаются.

### С графа на карточку

Клик по узлу (не drag) **открывает карточку** `/card/{путь}`: Markdown и
локальный граф сбоку. То же делают `[[wikilink]]` и хит `/search`.
Адрес карточки — GraphNotes, не GitHub и не «скачать файл». Холст — `/graph`.

Гость читает **опубликованную общую**. Личное, очередь и комментарии — после
входа; без права гостя можно отправить на вход, после входа — на ту же
карточку, если она ему доступна. Чужое платное и закрытый срез — замок,
не Markdown.

### Страница карточки

Отдельный экран, не только side panel на графе.

На странице:

- заголовок карточки;
- **отрисованный Markdown** (не сырой `<pre>`): заголовки, списки, цитаты,
  выделение, код, таблицы, обычные ссылки, `[[wikilinks]]` как переходы на
  другие карточки **того же слоя**, что открытая страница (с той же проверкой
  доступа);
- кнопка **«История правок»** (§6.4.1 / ТЗ 2.94): историю **не** грузят
  вместе с карточкой. По нажатию — последние **30 редакций**: кто, когда и
  что изменилось в тексте. Имя человека — ссылка на `#/users/{uuid}`;
- **«К графу»** — `/graph` (весь холст) с фокусом на этот узел (своя личная
  карточка переключает слой на «ваша личная ризома»). Локальный граф —
  отдельное управление на холсте (§6.5.1), не этот возврат.

Карточка **только на чтение** (ТЗ **2.93**). Кнопки **«Отредактировать
карточку»** нет ни у кого: своей личной, общей, чужого личного
(`personal:{uuid}:…`) и правки очереди. Hash `#/card/personal:{путь}` /
`personal%3A…` — переходный класс своего слоя, не канон и не редактор.
Роль `admin` не даёт правку опубликованной общей. Намёка про договор на
карточке нет.

`PUT /api/personal/notes/{path}` остаётся для **плагина / API** и для
создания пустой личной с висячей ссылки (ТЗ 2.66, пустой `expected_hash`),
не для браузерного редактора. Общую и чужую карточку этот PUT не пишет.
Устаревший `expected_hash` — 409. Чтение — `GET /api/cards/{path}`:
опубликованная общая — и гостю; личное и очередь — сессия.

**История правок (ТЗ 2.94 / 2.96).** Храним последние **30 версий** файла,
чтобы можно было **откатить** (откат из UI — leftover). Открытие карточки
**не** вызывает ленту и не тянет редакции. Кнопка **«История правок»**
запрашивает `GET /api/cards/{path}/revisions`: кто, когда, номер и
**unified diff**. **Индекс, граф и Differ** читают только последнюю рабочую
копию. Гость читает редакции опубликованной общей. Чужой личный — 404,
кроме admin. Предложение очереди — пустой список. Старая лента
`GET /api/cards/{path}/feed` остаётся для вклада, на карточку сама не
грузится. Личные редакции не смешиваются с общей того же git-пути.
Комментарии — на общей карточке, не на личной и не на правке очереди.

Страница общей не говорит «авторство только во внешнем git»; путь в общую —
`/offer` (сверка Differ внутри).

**Когда снова включить редактор.** Обратной выгрузки склада → vault / диск
пользователя в продукте нет. Пока её нет, in-app Markdown-редактор
выключен. Когда появится **обратная загрузка / обратная синхронизация** —
включают тонкий редактор **своей** личной карточки (как в ТЗ 2.48–2.53:
сначала чтение, затем MDXEditor, `PUT` в локальный склад). Когда можно
будет **взять карточку другого участника себе в ризому**, для тех
карточек — редактура и обратная синхронизация. Это leftover: не
восстанавливать исторический `take-from-shared` и не делать второй Obsidian
(live preview, autocomplete `[[ ]]`, backlinks как продукт). ADR-008
остаётся: GraphNotes — публикатор, не клон vault.

`[[wikilink]]` резолвит уникальный basename (файл в любой папке), полный путь
или уникальный title/alias, после Unicode NFC. Папка-заметка
`GraphNotes/GraphNotes.md` побеждает одноимённый файл в корне: `[[GraphNotes]]`
и заголовок GraphNotes ведут на неё. Имя папки или gitlink GraphNotes — не узел
«нет заметки»: индекс обходит gitlink и читает вложенный `.md`. Wikilink на
закрытый узел — замок, не тело. Wikilink на **несуществующий** узел открывает
`/card/{путь}` без тела: гость читает «карточки пока нет»; вошедший на этой
странице и в плашке при **наведении** на ссылку может **создать личную** карточку
(договор автора; склад у нас). Это не запись в общую.

Платёжный шлюз сюда не входит: страница просто соблюдает фильтр §5.6.

### 6.5.3. Следующая итерация поиска (ADR-015)

Сейчас `/search` ищет по индексу PostgreSQL и **остаётся SQL**, пока не
начнётся итерация ES. Следующая итерация — Elasticsearch как **производный**
поисковый индекс (как граф): Git остаётся каноном, ES можно пересобрать.
**Владелец (2026-09-12 / ТЗ 2.83):** итерация ES начинается **только после
первой утверждённой выкатки на production `rhizome`**. Не сейчас, не эта
ветка, не текущий Compose. Открытые вопросы 1–9 ниже остаются на ту волну;
ответы не выдумывать.

**Уже решено (минимальная планка):**

- тот же доступ, что §5.6 / §6.5.2: гость — только опубликованная общая;
  `user` — своя + общая; `editor` — плюс правки очереди; `admin` — все
  открываемые карточки; чужой личный в чужой выдаче не светятся, кроме
  admin и слоя `proposal` у editor;
- гость читает **тело** опубликованной общей на `/card/{путь}`; личное,
  очередь, лента и комментарии — нет;
- сниппет из тела в выдаче гостю **выключен**, пока владелец явно не включит;
- те же адреса `/search` и `/card/{путь}`;
- SQL-поиск живёт, пока ES не проходит те же проверки доступа; пустая выдача
  на время миграции запрещена;
- документ поиска привязан к той же revision, что граф; закрытый/снятый путь
  не зависает в чужих хитах.

**Вопросы владельцу — без ответа в код ES не идём:**

1. Индексировать **тела** опубликованных заметок или только метаданные
   (название, путь, теги, заголовки)? *Предложение: тела опубликованных — да.*
2. Индексировать **личный слой** вошедшего? *Предложение: да, только его UUID.*
3. Гостю в выдаче цитата из тела или только название / путь / теги?
   *Предложение: без цитаты из тела.*
4. Сразу русская морфология / опечатки или сначала точные токены?
   *Предложение: русский анализатор, без fuzzy-ML.*
5. Несколько тегов: И или ИЛИ? *Предложение: И.*
6. Фасеты кроме тегов (папка, автор, дата, степень узла)? *Предложение: в
   первом срезе только теги.*
7. Ранжирование: только текст или ещё свежесть / вклад / степень?
   *Предложение: сначала только текст.*
8. Где крутится: Compose на rhizome-test/rhizome или облако? OpenSearch, если
   лицензия Elastic мешает? *Предложение: свой Elasticsearch в Compose,
   без лишнего публичного порта; лицензию проверить до Stage-файла.*
9. Свежесть: тот же job, что индекс графа по SHA, или отдельный near-realtime?
   *Предложение: тот же SHA, что граф.*
