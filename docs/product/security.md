## 16. Безопасность чтения (антипарсинг)

Принято владельцем (ТЗ 2.80). **Не текущая волна и не `rhizome-test`.**
Ставить только **после выкатки на прод** (`rhizome`). На тесте мало живого
чтения: пороги бессмысленны и мешают проверке карточек.

Это не §9.1 (пароли, ZIP-бомба, белый шум, права склада). Здесь — как
гость **читает опубликованную общую**, не забирая корпус скриптом.

Гость по-прежнему может открыть карточку общей (§5.6, §6.5.2): клик по
узлу, `[[wikilink]]`, хит поиска. Антипарсинг **не** закрывает публичное
чтение и **не** ставит капчу на каждую карточку (это сломает публикатор).
Личное, очередь, комментарии, Differ гостю и так закрыты.

Перед кодом нужен ADR: режется перебор, не модель «гость читает общую».
Redis, Cloudflare и отдельная антибот-коробка сами по себе не следуют
из этого раздела.

### 16.1. Что ловим

Основной сигнал: **один адрес → много разных карточек** за скользящее
окно (минута и десять минут), не календарная «минута с :00».

- Считаются **уникальные** пути опубликованных карточек
  (`/card/{путь}` и тот же `GET` тела). Повтор той же карточки — не
  перебор.
- Второй сигнал — **доля корпуса**: заметная часть опубликованных
  карточек с одного адреса за короткое время — дамп, даже если RPM
  «мягкий».
- Третий — **форма обхода**: подряд по алфавиту путей; все хиты поиска
  подряд; все узлы страницы графа без паузы; много параллельных GET.
  Человек идёт локальным графом: карточка → несколько соседей, пауза.
- Лимит только на тела карточек **недостаточен**: гость может сначала
  выгрузить граф и поиск, потом идти по списку. Те же правила — на
  гостевой граф и поиск.

Адрес — IP; если крутится последний октет — смотреть `/24`. Вошедший и
гость — **разные корзины**. Ключ плагина при компрометации по-прежнему
отзывают в кабинете (§5.5.7), не баном IP кабинета.

### 16.2. Что отвечаем

По ступеням, не вечный бан с первого раза:

1. замедлить (`Retry-After`);
2. 429;
3. временный блок этого IP (минуты–часы);
4. временный блок `/24`, только если адрес прыгает в подсети.

Вечный бан IP — не автомат (офис, школа, мобильный NAT). Admin снимает
временный блок. Пороги **не** загадываются в ТЗ: снимаются с живого
прода после выкатки; admin их видит и может сдвинуть.

### 16.3. Что не входит

- капча на публичную карточку;
- бан за обновление одной и той же карточки;
- lock учётки гостя (у гостя её нет);
- zip-бомба / белый шум / лимит плагина 120/мин — уже §9.1 и §6.3.4;
- отдельная база логов и Redis «под антипарсинг» — не этот раздел
  (отдельная база логов — leftover ТЗ 2.74).
