## 5. Глобальные пользовательские роли

GraphNotes MVP использует три глобальные иерархические роли:
`user < editor < admin`. Какой **уровень доступа к ризоме** видит человек
(опубликованное / свой закрытый срез / чужой закрытый срез при entitlement) —
не роль, а фильтр: [access.md](access.md) §5.6, ADR-016.

### 5.1. User

- регистрируется с **обязательной почтой** и входит по логину/паролю **или**
  входит почтой и паролем учётки [vsepsy.ru](https://vsepsy.ru/) на этой
  инсталляции ([vsepsy-identity.md](vsepsy-identity.md) §6.1.3), без второй
  регистрации того же адреса. **ТЗ 2.86 / §17:** новой учётки с улицы
  нет: только ссылка из письма-инвайта, окна «Регистрация» нет; инвайт
  может выдать любой с учёткой;
- читает единую общую ризому **в приложении** (граф, карточки, Markdown на
  чтение); файлами общую не забирает;
- на **`/user`** видит **одно** личное хранилище: по умолчанию склад
  GraphNotes (плагин / API — **бесплатный** вход локального графа, ТЗ 2.82;
  загрузки `.md`/ZIP с сайта нет, ТЗ 2.96; in-app правка выключена, ТЗ 2.93).
  Свой git —
  необязательный коннектор (copy-in). Там же личные данные и договор автора
  ([user-settings.md](user-settings.md) §5.5);
- на вкладке **Предложения** (`/offer`) видит сверку Differ (ТЗ 3.01):
  отличия **текущего** личного хранилища к общей; отдельной вкладки
  «Отличающиеся» нет;
- на сайте видит, что ризома смотрит его склад: может сам предложить карточку;
  ризома может пометить те, которых в общей нет, и предложить темы (§6.6.3);
- создаёт предложение из выбранных отличий Differ;
- видит **свои** предложения на `/offer`; текст — та же таблица wikidiff2,
  что у editor (ТЗ 3.03); возврат и отклонение приходят с комментарием редактора;
- в **`/search`** ищет по **своей** и **общей** ризоме; слой
  карточки подсвечен; чужой личный vault в выдаче не видит;
- видит граф ризомы на `/graph` (по умолчанию ризома, ТЗ 3.00). Вкладки
  «Мой граф» нет. Свой личный слой — фильтр на том же холсте: из git,
  если подключён; иначе из серверного хранилища. **«ваша часть ризомы»** —
  пересечение с общей; **«ваша личная ризома»** — полный личный слой,
  не отдельный адрес. Не «ваш git»; человек не курирует состав слоёв вручную;
- видит свой авторский вклад на `/contribution`: что написал, какие связи
  сделал, что ещё только в личном складе, что предложено, что принято в общую;
- не теряет этот след, когда Differ по принятым путям пустеет;
- публичная карточка человека — `#/users/{login}` (ADR-012 / ТЗ 2.60 / **2.97**), не `/user`;
- на `/contribution` видит **свою** статистику вклада (§5.4.2), чужую
  подробную статистику не видит; чужую **публичную** карточку открывает;

Авторство заметок: личный склад (у нас / необязательный git) **и** общий слой
GraphNotes. In-app правка — только **своей** личной карточки; общую автор
предлагает через Предложения (Differ внутри).

### 5.2. Editor

- имеет все права `user`;
- рассматривает очередь предложений **авторизованных** в **опубликованную**
  общую на **`/queue`**: принять, отклонить, вернуть, откатить;
- очередь — три вкладки: **Новые** (ещё не трогал), **В работе** (вернул
  автору с комментарием), **Отклонённые** (не принял, комментарий остаётся
  у автора); свои заявки автора — на `/offer`, не здесь;
- открытие предложения: **сначала текст** предлагаемых карточек и связи,
  **потом** ризома (Graph Diff);
- в **`/search`** ищет свою + общую + **правки, которые дали на ревью**;
- **не** ревьюит закрытый срез (платный уровень доступа): он не предложение
  и не работа editor’а (§5.4.1, §5.6);
- видит автора, человеческий текстовый diff **как у Википедии**, посчитанный
  **wikidiff2** (ТЗ 3.03: две колонки «В ризоме / В предложении»; новая
  карточка — слева пусто),
  состав Differ, какие заметки и связи автор предлагает, и (Stage 8) Graph Diff;
- может зафиксировать правку общей ризомы аудируемым Git commit без требования
  полноценного in-app редактора;
- не может принять собственное предложение;
- имеет карточку editor’а и **редакторскую статистику**: сколько предложений
  принял / отклонил / вернул / откатил, **какие** правки (предложения, карточки)
  и **какие связи** в общей он принял или отклонил — отдельно от своего
  авторского вклада;

### 5.3. Admin

- является суперпользователем и имеет все права `user` и `editor`;
- управляет пользователями, ролями, блокировками и системными настройками;
- административное окно не смешивается с графом, Differ и очередью предложений:
  у `admin` отдельная вкладка «Администрирование»;
- вкладка «Администрирование» — отдельное окно с разделами **«Пользователи»**,
  **«Журнал»** и **«Установка»**, не одна форма на настройках
  и не `/ops` vsepsy;
- карта инвайтов — страница **`#/invites`** (§17.5 / ТЗ 2.98), на тесте
  `http://172.16.13.14:8080/#/invites`; для создателей: у кого сколько
  связей; не раздел админки; сейчас только `admin`; Code Writer выкладывает
  на `rhizome-test`;
- на «Пользователи» admin ищет и фильтрует учётки, **создаёт учётку** (роль
  может назначить сразу; публичная регистрация по-прежнему только `user`),
  меняет роль, блокирует, задаёт пароль, сбрасывает сессии, включает/выключает
  уведомления очереди (почта / Telegram-канал, §5.5.6) у `editor`/`admin`
  и видит последний вход, подтверждение почты и число сессий;
- **журнал действий** живёт в базе GraphNotes; admin открывает его отдельным
  экраном с фильтрами по действию, кто сделал и времени (не файл лога сервера
  как единственный след);
- «Установка» показывает health приложения и базы, статус SMTP без секретов,
  **публичный адрес сайта** (поле, сохраняется в базе; им пользуются ссылки
  в письмах), **стартовую карточку** `/card` (**вывод:** UUID или git-путь;
  пишет только admin; если не задана — `/card` отвечает 404), проверочное
  письмо и кнопки подключить общую ризому / пересобрать индекс;
- видит **статистику по всем пользователям**: вклад каждого (карточки, связи,
  что предложено / принято) и, для editor, решения по правкам и связям;
- вкладку «Администрирование» видит только `admin`; `user` и `editor` её не видят;
  сменить чужой пароль и читать журнал действий они не могут;
- управляет привязкой GitHub-ресурсов и пересборкой индекса;
- **Видит закрытые срезы** на графе и в карточках (как admin, не как
  «всем выдан платный уровень»);
- в **`/search`** ищет по всем открываемым карточкам (общая, все личные
  слои, очередь правок); слой подсвечен;
- рассматривает предложения и может зафиксировать аудируемый Git commit в общую
  ризому без требования in-app редактора;
- административные и редакторские действия обязательно аудируются **в базе**
  (§6.8): кто, когда, над кем, какое действие; пароль и токен в запись не
  попадают;
- не может обходить Markdown/Git source of truth и правила согласованности.

Только `admin` назначает и отзывает роли. Последний действующий
admin защищён от случайного удаления/блокировки или имеет проверенную recovery
процедуру. Смена пароля последнему admin **разрешена** (это не снятие роли).
Ни один набор прав не может обходить Markdown/Git source of truth.

#### 5.3.1. Смена пароля администратором

Нужно, когда человек забыл пароль или учётка скомпрометирована. Почтовый вход
кодом и **сброс пароля по письму** (§6.1.2) не заменяют действие admin: admin
по-прежнему задаёт новый пароль с экрана «Пользователи».

- `admin` задаёт **новый** пароль выбранному пользователю с экрана
  «Пользователи». Текущий пароль прочитать нельзя: его нет в открытом виде.
- Новый пароль хранится только как `password_hash`. В журнал, API-ответ и
  логи процесса открытый пароль не попадает.
- После смены прежние сессии этой учётки заканчиваются: войти можно уже
  новым паролем.
- `editor` и `user` чужой пароль не меняют. Свою смену пароля в Настройках
  этот пункт не отменяет и не требует: канон здесь — действие admin.

### 5.4. Автор и юридический блок

Глобальная иерархия `user < editor < admin` остаётся канонической, но
дополнительно GraphNotes поддерживает продуктовый статус **автора**
(ADR-010). Это не четвёртая RBAC-роль.

- Статус автора включается только после принятия юридического договора.
  Каноническое место — **Настройки → Договор автора** ([user-settings.md](user-settings.md)
  §5.5.3), не первый экран графа. Если договора ещё нет, вклад (git / Differ /
  предложение) ведёт туда.
- GraphNotes хранит, кто принял, когда, какую версию договора, и когда
  статус отозван; повторное принятие снова включает вклад.
- Видимый текст договора (версия `2026-09-05`) — только в **Настройках →
  Договор автора**, не на **О программе**:
  - принимая договор, человек несёт ответственность за содержание своих
    заметок и связанных с ними связей, которые предлагает в общую ризому;
  - статус автора можно отозвать: GraphNotes запишет время отзыва; новые
    предложения, загрузки как вклад и подключение git как вклад недоступны,
    пока договор не принят снова; заметки, уже принятые в общую, остаются
    в её git;
  - все карточки, предложенные в общую, — лицензия WTFPL
    (https://ru.wikipedia.org/wiki/WTFPL): с этим текстом можно делать что
    угодно;
  - программное обеспечение — GNU Affero General Public License v3.0;
    разработчик Юрий Ефимов, y@psychoanalyst.pro.
- GraphNotes по-прежнему записывает, кто принял, когда и какую версию
  (не второй канон Markdown и не платёж). Это служебная запись, не абзац
  «депонирования» в тексте договора. ADR-010 про статус автора и вклад
  остаётся; видимый текст — этот канон (ТЗ 2.44).
- Действия вклада (подключить git, загрузить `.md` как вклад, Differ,
  предложить) требуют активного статуса автора. Чтение общей, статистика
  вклада §5.4.2, очередь editor/admin и администрирование — нет.
- У каждого аккаунта есть **карточка человека** `#/users/{login}`
  (ADR-012; **не** `/user` — там настройки, ТЗ 2.58). «Мой вклад» —
  `/contribution`. Из ленты карточки ризомы имя открывает эту страницу.
  Автор и «просто вошедший» — **один уровень входа** (§5.6): **уровни доступа
  к ризоме** — какой срез показать, не отдельный логин (ADR-016).
  - `user` — кто вошёл: имя, роль, есть ли git; вклад в общую может быть пуст;
  - `editor` — плюс редакционная статистика очереди (рассмотрел / принял /
    отклонил / вернул / откатил);
  - `автор` — плюс публичный корпус в общей и, в отличие от `user`, **закрытый
    срез** (в том числе **платный уровень доступа**), который автор держит у себя.
- Публичная **карточка пользователя** `#/users/{login}` (ТЗ 2.95 / **2.97**) одна и та
  же для гостя и вошедшего: лицо, имя, «Приглашен … от @user»; числа —
  карточки и связи **в личном складе**, карточки и связи **предложенные в
  ризому**, объём предложенных правок (Б/КБ/МБ). Тела чужих личных файлов,
  пути закрытого среза и журнал admin не показываются. Принятые в общую
  карточки можно открыть с этой страницы. §17 / ТЗ 2.87:
  **«Приглашен %date% по приглашению от %@user%»** — `%@user%` это
  логин пригласившего (`@user`), ссылка на его карточку. Нет
  пригласившего — строки нет. На выкатке 2.89 существующие учётки
  кроме `efimov` показывают `@efimov`.
- **Ачивка для интернета** (граф вклада, число заметок или другой параметр;
  вставка на vsepsy.ru и «данные для моего сайта») — §6.1.4. Автор включает
  сам. Какие поля карточки светить **всем** — ещё не решено; до решения
  показ по умолчанию выключен.

#### 5.4.1. Закрытый срез и платный уровень доступа: где хранить

Отличие автора от обычного `user`: автор может **не отдавать** часть своего
личного склада в опубликованную общую. **Платный уровень доступа** — тот же
закрытый срез: тело видно только с этим уровнем. Шлюз оплаты позже только
**выдаёт уровень**; он не меняет хранение (ADR-016).

**Хранение: тот же личный склад, не второй репозиторий**

- Канонический текст закрытых заметок — **личный склад автора** (у нас или
  XOR git), не второй GitHub knowledge repository и не второй канон
  опубликованной общей в PostgreSQL. Второй «платный» shared-репозиторий
  запрещён: это была бы вторая общая ризома (ADR-007), второй Differ и утечка
  тел при clone.
- Маркировка в Markdown: соглашение о пути и/или frontmatter с именем уровня
  доступа. Снять метку **не** публикует файл в общую.
- Закрытые пути **не входят в Differ** и не сливаются в общую. GraphNotes не
  отдаёт и опубликованную общую файлами, поэтому закрытое тем более не
  утекает ZIP/clone’ом продукта.
- GraphNotes хранит только производное: «этот путь закрыт / какой уровень»,
  владелец-UUID, **entitlement** (какие UUID имеют этот уровень). Editor
  **не** берёт это в очередь. Не второй канон Markdown.

Иначе закрытое нельзя класть в опубликованную общую **и** нельзя делать
внешний git продуктовым download: clone/ZIP отдали бы корпус.

**В общей ризоме и в виде «ризома автора»**

- Гость и авторизованный **без этого уровня доступа** видят **опубликованное**.
  Узлы закрытого среза им не открываются; ссылка с общего на закрытое —
  **замок**, не тело и не unresolved.
- Автор среза, UUID с **уровнем доступа** к этому срезу и **admin** открывают
  карточки среза. После entitlement это отдельный **вид** «ризома автора»
  (граф и карточки помеченных путей), не второй git и не весь личный склад
  автора (§5.6.4). «Загрузить» = открыть этот вид в приложении, не скачать
  файлы.
- GraphNotes не отдаёт ZIP и не предлагает clone общей **и** закрытого
  корпуса как UX.
- Закрытое **не** идёт в Differ и **не** ревьюится editor’ом.
- Overlay своего закрытого — у владельца (и admin); не «чужая ризома» для
  остальных без уровня. Чужой открытый личный склад как публичная витрина
  не принят (§12 п. 9).

Платёж не меняет место хранения: меняется список UUID с уровнем доступа.
`admin` может выдать уровень без шлюза. Модель «кому видно» — §5.6.

#### 5.4.2. Статистика по пользователям

Статистика — производные данные GraphNotes (лента взаимодействий), не git log
и не тела заметок в PostgreSQL.

**Каждый `user` / автор видит только свою:**

- какие карточки ризомы трогал (создал, правил текст, предложил);
- что **добавил** (заметки и связи в личном слое / Differ);
- что **приняли** в общую (заметки);
- какие **связи добавил**;
- какие **связи приняли** в общую.

Чужой такой разбор ему недоступен. На публичной карточке автора — счётчики
публичного вклада (принятые заметки и связи, число предложений, созданных
карточек и правок в общей), не чужой подробный журнал.

**Editor дополнительно видит свою редакционную статистику:**

- сколько предложений принял, отклонил, вернул, откатил;
- **какие** правки (какие предложения / карточки) он так решил;
- **какие связи** в общей он принял или отклонил вместе с этими правками.

Это не его авторский вклад, а работа по очереди.

**Admin** на «Администрирование → Пользователи» видит ту же статистику
**по всем** учётным записям: и авторский вклад, и редакционные решения.
Вкладка по-прежнему только у `admin`.

Уровень ниже автора: любой вошедший может оставлять комментарии
(ADR-014, не четвёртая RBAC-роль); editor/admin модерирует. Авторский
договор для комментария не нужен.

#### 5.4.3. Карточка пользователя

Сущность **карточка пользователя** — публичная страница человека
`#/users/{login}` (ADR-012 / ТЗ **2.95** / **2.97** / **2.98**). Канон —
логин: `#/users/efimov`. Публичный UUID в адресе и в JSON карточки
запрещён: внутренний id не идентификатор для интернета. Это не `/user`
(настройки) и не «Мой вклад» (`/contribution`).

Гость и вошедший видят **одну и ту же** карточку:

- лицо, отображаемое имя, логин, роль, статус автора;
- публичное описание: сайт, Telegram и телефон, если владелец их открыл;
- кто пригласил: «Приглашен %date% по приглашению от @user» (нет
  пригласившего — строки нет);
- сколько карточек в **личном складе**;
- сколько связей в **личном складе**;
- сколько карточек он **предложил в ризому**;
- сколько связей он **предложил в ризому**;
- объём предложенных правок в карточках — байты, килобайты или мегабайты.

Числа — счётчики, не тела и не пути чужого личного склада. Закрытый срез
и журнал admin на эту страницу не входят. Принятые в общую карточки можно
открыть с карточки пользователя. Без сессии адрес `#/users/{login}` не
подменяется графом.

Юридический договор автора принят в ADR-010. Закрытый корпус — ADR-011.
Карточка пользователя — ADR-012. Лента карточки ризомы — ADR-013.
Commenter — ADR-014. **Уровни доступа к ризоме** — ADR-016: не роль
«потребитель»; платный уровень = закрытый срез; тот же git + маркировка;
вид «ризома автора» после уровня — экран среза, не вторая сущность;
шлюз оплаты — позже.
