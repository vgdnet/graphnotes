Статус: CANONICAL / LIVING DOCUMENT  
Версия: 3.06  
Обновлено: 2026-09-12

Это **оглавление**. Требования живут в связанных файлах, не в одной простыне.
Номер раздела (§5.4, §6.1) тот же, что в файле раздела.

Документ создан на основе PDF `GraphNotes_TZ_GitHub_Password_MVP_RU.pdf` 1.2
(2026-08-15). Принятые ADR имеют приоритет над исходным PDF.

ТЗ не журнал переписки. Глобальное изменение: явное решение → ADR → этот набор
файлов и `MASTER_CONTEXT.md`. Поставленное в продукт поведение (UX, тема,
экран, правило доступа) сразу пишется сюда **и** в техническое ТЗ; одного
обсуждения мало (§13.4).

**ТЗ 2.99 — порядок поставки:** сначала **продуктовое ТЗ** (что видит
человек: экран, hash, кто видит), потом **техническое ТЗ** (`MASTER_CONTEXT`,
контракт, выкладка), потом Code Writer **выкладывает на `rhizome-test`**.
Не наоборот: не код/тест, а ТЗ «потом». Чат не канон. На тесте карта
инвайтов — `#/invites` (`http://172.16.13.14:8080/#/invites`), не
`#/api/graph/invites`.

**ТЗ 3.05 — канон всегда один.** Product editor, technical editor, code
writer, наблюдатели, агенты Codex/Cursor читают одну истину: этот набор
файлов, `MASTER_CONTEXT.md`, принятые ADR. Нет второго Markdown-канона,
нет чата как спецификации, нет личного ТЗ у агента. Если код и ТЗ
расходятся — остановиться. Leftover в runtime — недописанный код, не
второй канон. Движок editor-diff — native C++ **wikidiff2** (ТЗ 3.03 /
ADR-018); `php-cli` в образе — дырка в коде, не канон.

## 1. Назначение

Согласованное продуктовое ТЗ: для кого продукт, роли, функции, границы MVP,
критерии приёмки. Реализация и стек — не здесь (`MASTER_CONTEXT`, стадии).

## Куда смотреть по задаче

- **Локальный склад у нас** (ТЗ 2.61–2.63): GitHub, git, позже Dropbox / Google Drive — только **источники**. Продукт **копирует** `.md` в локальное хранилище (личное и опубликованная общая). Граф, карточки и Differ читают копию. → [vision.md](vision.md), [principles.md](principles.md) §3.1–3.4, [functional.md](functional.md) §6.2–6.3
- **ZIP загрузка (ТЗ 2.65 / leftover 2.96):** лимиты архива остаются. **Кнопки загрузки `.md`/ZIP на сайте нет** (в т.ч. в Differ). Сейчас в личный склад пишет **плагин**. Когда вернём загрузку с сайта — только **API, который синхронизирует в локальный склад** (как плагин), не второй канон. → [functional.md](functional.md) §6.3
- **Белый шум (ТЗ 2.67):** мусор (не заметки) в личном ingest не индексируется; учётка блокируется (`is_active`); admin’ам письмо. Настоящие уже проиндексированные заметки не удаляются. → [functional.md](functional.md) §6.3, [acceptance-and-nfr.md](acceptance-and-nfr.md) §9.1
- **Публикатор / плагин (ТЗ 2.68–2.91 / §6.3.4):** vault и личное хранилище — **одна копия**; локальное побеждает; UI «конфликты» нет (ТЗ **2.91**). Бесплатный вход в личное, не в общую. Автозапись — ТЗ 2.90: кнопка **«Передать правки на сервер»** в виде боковой панели Obsidian; лента paper-plane тоже пишет. Differ / отдать в общую из плагина — **не пишет в общую** (§6.6.3). Differ в API отдаёт список и пару текстов одного пути; тем же маршрутом пользуются `/offer` и плагин Card Merge (ТЗ **3.04**). Очередь карточек для правки в плагине — **боковая панель**, тот же `GET /api/differ` (ТЗ **3.06**), не сайт `/queue`. В общую по-прежнему только предложение и очередь editor’а. → [functional.md](functional.md) §6.3.4, §6.6.3, [user-settings.md](user-settings.md) §5.5.7, [api.md](api.md)
- **Публикатор, карточка и боковой граф** (ТЗ 2.64): клик по узлу и `[[wikilink]]` открывают `/card/{путь}`; сбоку локальный граф. Гость читает опубликованную общую. → [search-and-card.md](search-and-card.md), [access.md](access.md) §5.6, [functional.md](functional.md) §6.5.1
- **Антипарсинг чтения общей (ТЗ 2.80 / §16):** один адрес → много разных карточек; доля корпуса; обход не по соседям; сначала 429, не вечный бан IP. **После выкатки на `rhizome`.** На `rhizome-test` не ставить. Капча на каждую карточку — нет. → [security.md](security.md)
- **Инвайты (ТЗ 2.84–2.87 / §17, поставлено 2.89 / карточки 2.92 на `rhizome-test`):** без инвайта учётки нет. Инвайт — **письмо со ссылкой**; окна «Зарегистрироваться» нет. На карточке человека, в «Мой вклад», в настройках и в админке на строке учётки: «Приглашен %date% по приглашению от @user». Текущие учётки (кроме зерна `efimov`) — от `@efimov`. То же на vsepsy.ru. **Карта инвайтов** (ТЗ **2.98**): страница **`#/invites`** (на тесте `http://172.16.13.14:8080/#/invites`); API `GET /api/graph/invites` — не hash. Для создателей: у кого сколько связей. Только `admin`. Code Writer выкладывает на `rhizome-test`. → [invites.md](invites.md) §17.5
- **Нет такой карточки (ТЗ 2.66):** гость — «карточки пока нет»; вошедший создаёт личную с этой страницы и из плашки при наведении на висячую ссылку. → [search-and-card.md](search-and-card.md)
- **In-app редактор выключен (ТЗ 2.93):** на сайте файл не правят. Обратной выгрузки склада GraphNotes → vault / диск пользователя нет — править в браузере незачем. Редактор включают, когда появится **обратная загрузка / обратная синхронизация**. Когда можно будет **взять карточку другого участника себе в ризому**, для тех карточек — редактура и обратная синхронизация.
