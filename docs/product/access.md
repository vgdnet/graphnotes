## 5.6. Стартовая страница и модель доступа

Холст ризомы — **`/graph`** (fCoSE). По умолчанию на нём **граф ризомы**
(ТЗ **3.00**). Вкладки «Мой граф» и адреса `/my_graph` **нет**; старый
`#/my_graph` открывает `/graph`. Стартовая **карточка** — **`/card`**, её
выбирает admin в настройках инсталляции (не папка слоя). Граф **не** снимается:
оба адреса канон (ТЗ 2.58). Гость видит узлы опубликованной общей на `/graph` и **открывает карточку**
опубликованной общей: клик по узлу, `[[wikilink]]` и хит поиска ведут на
`/card/{путь}` с Markdown и локальным графом сбоку. Перебор корпуса
гостем режется **после прода** (§16 / ТЗ 2.80), не на тесте. Висячая ссылка: гость
видит «карточки пока нет»; вошедший может создать личную (ТЗ 2.66). Личное,
очередь и комментарии — после входа. См. [search-and-card.md](search-and-card.md).

**Вывод:** лендинг **`/`** владелец не переопределил. Пока «старт = граф»
значит `/` → `/graph`. Если `/` должна открывать стартовую карточку — отдельное
слово владельца.

После входа человек не обязан попадать на настройки: git и договор — на
**`/user`** ([user-settings.md](user-settings.md); имя в шапке ведёт туда).

Права на запись по-прежнему проверяет backend по UUID и назначениям. Вид
графа — не граница безопасности (§3.5).

### 5.6.1. Роли — не уровни доступа

Иерархия **ролей** остаётся `user < editor < admin` (назначает только
`admin`). Это **грубый шлюз** админки, очереди и учёток, пока нет
покарточных проверок (ТЗ **3.24**). Показ карточки и действия с
карточкой идут через **права на карточке**, не только эту лестницу
(§5.6.7). **Уровни доступа к ризоме** (ADR-016) — не отдельный логин.
Это фильтр закрытого среза одной ризомы. Как он стыкуется с
покарточным ACL — открытый вопрос, ответы не выдумывать.

Владелец назвал четыре **класса доступа**: пользователь, editor, admin,
**платный контент-мейкер**. Платный контент-мейкер — класс контента и
прав, не workspace / org / team и не вторая общая ризома. Чем он
отличается от `user` и от `editor`, и станет ли четвёртой RBAC-ролью
(поправка или замена ADR-007) — открытый вопрос.

| Что есть | Что это |
| --- | --- |
| Гость | Нет сессии. Публичный уровень: граф и **карточки** опубликованной общей |
| Сессия `user` / `editor` / `admin` | Роль RBAC. Карточки **опубликованного** уровня; Differ/предложение по правилам §5.4 |
| Автор | Статус договора на том же UUID. Может держать **закрытый срез** в своём git |
| **Платный уровень доступа** | Закрытая часть контента. Тело видно только с этим уровнем (автор среза, UUID с entitlement, `admin`). Не роль «потребитель» |
| Editor | Роль. Очередь в **опубликованную** общую. Закрытый срез **не** модерирует. Набор редакционных прав можно сузить **тегами карточек** (§5.6.5) |
| Admin | Роль. Видит закрытые срезы как admin, не «оплатил за всех» |

Обычный авторизованный без уровня на чужой закрытый срез видит замок, не
тело (§5.4.1), пока `admin` (или позже оплата) не выдаст уровень.

### 5.6.2. Что видно на графе

Один граф, разный **фильтр по уровню доступа**:

- **Гость** — только опубликованная общая. Без чужого и своего личного overlay,
  без закрытых узлов. Карточку общей открывает (клик по узлу / ссылка).
- **Авторизованный** — опубликованная общая + **свой** личный слой на графе:
  из git, если подключён; иначе из серверного хранилища. В меню слоя два
  имени, не «ваш git»: **«ваша часть ризомы»** — пересечение с общей
  (текущий overlay: личные заметки, которые сами ссылаются на видимую
  страницу общей), не весь личный склад; **«ваша личная ризома»** — полный
  проиндексированный личный граф. Слои считает индекс автоматически:
  человек не составляет вручную, какие заметки — «часть», какие — личная
  ризома. Карточки и база изменений (лента / Graph Diff) читают ту же
  видимость, не второй каталог. Чужой закрытый срез — нет, пока нет
  **уровня доступа** к нему.
- **Автор** — как авторизованный, плюс **свой** закрытый срез (не вторая
  ризома, не второй git-репозиторий знаний). Свой срез можно смотреть
  фильтром на `/graph` или видом «ризома автора» (§5.6.4).
- **Есть уровень доступа к чужому закрытому срезу** — как авторизованный,
  плюс вид «ризома автора»: граф и карточки этого среза (§5.6.4). Это
  метка entitlement на UUID, не роль.
- **Editor** — как авторизованный (и свой закрытый срез, если автор). Очередь
  — отдельно. Чужой закрытый срез не открывается и не ревьюится без уровня
  или без `admin`.
- **Admin** — опубликованное + закрытые срезы (видеть и открывать карточки).
  Не заменяет выдачу уровня остальным.

Закрытый / платный уровень **не** предложение в общую и **не** работа
editor’а. Шлюз оплаты — отдельное решение: он только **выдаёт уровень**.
Хранение — §5.4.1 и ADR-016: тот же личный склад (у нас XOR git), маркировка
путей, не второй knowledge repository.

### 5.6.4. «Два графа» и вид «ризома автора»

Согласовано с продуктологом (2026-09-04): «два графа» в письме владельца —
это **не** две базы и **не** вторая общая ризома.

- **Общая ризома** — карта на `/graph`. Git → индекс → граф, карточки, поиск,
  очередь. Авторы предлагают через Differ; editor принимает → commit в общий
  git → пересборка. Editor может ещё писать в этот же общий git напрямую
  (аудируемый commit), не вторым складом.
- **Свой слой** у вошедшего уже есть (Stage 6): общая плюс **своя** ризома
  (overlay / «ваша часть ризомы» / «ваша личная ризома»). На экране это
  **один граф с фильтром слоя**, не два отдельных мира.
- **Закрытый / платный срез** живёт в том же личном хранилище (git XOR
  файлы у нас), с маркировкой путей. Не второй knowledge repository.

После **уровня доступа** к закрытому срезу человек открывает **вид**
«ризома автора»: граф и карточки только помеченных закрытых путей. Это
экран/фильтр той же модели, не вторая сущность, не клон и не ZIP.

«Загрузить» в этом контуре — **открыть вид в GraphNotes** после entitlement.
Не скачать файлы в vault / Obsidian покупателя и не отдать закрытый корпус
продуктовым ZIP/clone.

Платный продукт — только помеченный срез. Весь личный склад (черновики,
кандидаты Differ) покупателю не отдаём.

Публичный поиск и комментарии живут на **опубликованной общей** (и на своём
слое себе). Чужой открытый личный репозиторий как витрина «все ищут,
находят и комментируют» **не принят**: это обошло бы очередь editor’ов и
§3.3. Открытый вопрос — §12 п. 9.

### 5.6.5. Права editor’а по тегам (ТЗ 3.21)

Роль по-прежнему `editor` (назначает `admin`). Четвёртой роли, workspace
и второго каталога тегов нет.

**Учёт доступа.** Editor может получить **набор редакционных прав только
на карточки с определёнными тегами**. Тег на карточке (тот же, что в
поиске и в Markdown) определяет, на какие карточки этот набор действует.

В набор входят уже существующие права editor’а на **опубликованную**
общую: видеть карточку в `/queue` и в Card Merge, принять / отклонить /
вернуть / откатить, Save & Resolve. Не выдумывать отдельный ACL
«читать абзац / прятать тело». Закрытый / платный срез по-прежнему не
очередь editor’а (ADR-016).

Выдаёт `admin` на карточке учётки (**Администрирование → Пользователи**):
список тегов этому UUID. Несколько тегов — карточка подходит, если на ней
есть **хотя бы один** выданный тег.

- Нет ни одного тега у `editor` — как сейчас: вся опубликованная очередь
  (существующие editor’ы не слепнут).
- Есть теги — очередь и решения **только** по карточкам с этими тегами.
  Файлы той же заявки без его тегов остаются в очереди для другого
  editor’а / `admin` (как одна карточка в ТЗ 3.18).
- `admin` видит и решает все карточки, теги его не режут.
- Свой договор и авторский Differ тегами editor’а не режутся.

Это не уровень доступа к закрытому срезу и не «платный тег». Тег здесь —
граница **редакционных** прав, не витрина гостю. ТЗ **3.24** добавляет
тег ещё как способ сменить **права показа и действий** сразу на много
карточек; наследование с тега vs override на карточке — открытый вопрос
(§5.6.7). Точные глаголы «прятать тело» не выдумывать.

### 5.6.6. Два склада editor’а (ТЗ 3.22 / **3.25**)

Путаница: «editor должен иметь доступ к общему» не значит, что общее
хранилище **подменяет** ему личное или что vault editor’а становится
**второй канонической** общей ризомой.

У каждого editor’а (как у любого `user`) **своё** личное хранилище —
свой UUID, свой vault, свой `personal_uploads`. Он работает с ним
**самостоятельно**, тем же Publisher, что автор: копия vault → личное,
Differ, предложить в ризому. Чужое личное ему недоступно.

**Общее** хранилище одно на инсталляцию (`shared_notes`, опубликованная
ризома) и **живёт на GraphNotes**. Доступ editor’а к нему:

- **читать** опубликованные карточки на сайте (граф, `/card`, поиск);
- **принимать правки от других участников** — сайт `/queue` или плагин
  Card Merge: принятие **только через editor’а**; «Принять в работу»
  качает **эту** карточку заявки (две стороны);
- **после принятия файла** (ТЗ **3.25**) — **две отдельные операции**,
  не одно «Save & Resolve = POST в общую»:
  1. всегда записать принятый файл в **локальный vault**; открытие
     карточки — эта локальная заметка; если запись не удалась —
     принятие не закончено;
  2. только если локальный файл ≠ файл в хранилище ризомы — обновить
     хранилище **от аккаунта editor’а** (доступ к общей; Differ —
     write gate); если файлы совпадают — вторую операцию пропускают;
- **не** выгружать всю ризому ZIP/clone в vault (ТЗ 2.5);
- **не** делать vault второй канонической общей.

**ТЗ 3.25 сужает 3.22.** Card Merge — очередь правок **от других
участников**. Принятие **через editor’а**. После принятия файла —
**две отдельные операции**, не одно «Save & Resolve = POST в общую»
(локальная запись всегда; обновление хранилища ризомы только если
локальный ≠ склад). Runtime, который сначала POST `/resolve`, потом
может записать vault, — **долг**. Фраза «никогда не класть общее в
Obsidian editor’а как склад» / «общее не клонируют в vault» больше не
читается как запрет локальной копии **принятых** карточек и не делает
эту запись leftover против 3.22. Канон опубликованной общей —
GraphNotes. Vault editor’а — **не** вторая общая ризома и **не**
«общее стало его складом». Differ / очередь — по-прежнему gate в
опубликованную общую. Открытие карточки после принятия — локальная
заметка (обязательный UX, не leftover 3.17–3.19).

Два контура, **один** плагин (ТЗ **3.26** снимает 3.09), один токен
`gnp_`. Очередь — capability того же клиента: показывают при открытии
Obsidian, если у учётки editor-доступ; иначе UI очереди выкл. Ручная
правка editor’а — тот же sync, что у участника. Каталоги
`obsidian-plugin/` и `obsidian-card-merge/` — leftover runtime, пока
один пакет не поставлен:

```text
свой vault  ←один плагин (sync как у участника)→  своё личное хранилище
свой vault  ←тот же плагин + очередь из API, если editor-доступ→
            склады GraphNotes; в опубликованную общую — через заявку
```

Card Merge **не** описывать как «только кэш `.obsidian`, никогда
заметка vault». Кэш `.obsidian/plugins/…/work/` остаётся черновиком
сравнения; **принятая** карточка — обычная заметка vault по пути
карточки.

**Два и больше editor’ов** уже сейчас в модели: одна очередь, одно
общее, у каждого своё личное. Принимают **параллельно разные**
карточки. Одну и ту же карточку в работу берёт **один** человек;
второй видит, что она занята (серверный слот — если локальный ТЗ 3.16
не виден другим). Теги (§5.6.5) режут, кто какие карточки видит.
Своё предложение принять нельзя.

После принятия каждого файла — **две операции** (ТЗ **3.25**): сначала
обычная заметка vault по пути карточки (без этой записи принятие не
закончено); потом, **только если** локальный файл ≠ файл в хранилище
ризомы, обновление хранилища **от аккаунта editor’а** (Differ — gate;
если совпадают — пропуск). Runtime POST `/resolve` сначала — **долг**.
Editor открывает **локальную** заметку новым листом не-MergeView
(`createLeafBySplit` / `getLeaf(true)`; шаги — `debug.log` плагина)
(ТЗ 3.17 / **3.19** / **3.25**). Очередь справа остаётся сбоку. Права
3.24 не меняются. Исторический `take-from-shared` корпуса и редактор
сайта (2.93) не возвращаем.

### 5.6.7. API показа карточки и права на карточке (канон, ТЗ 3.24)

Владелец (2026-09-13) принял **смену модели**: API **на карточку**,
иначе (только глобальная лестница) карточки не заработают. Вилка
«выбрать 0/1/2/3» и развилка §12 п. 12 (A срез / B карточка автору)
**сняты как выбор модели**. Выбрано: показ и права живут **на карточке**.
Это **канон**, не поставленный runtime. Маршруты и проверки в коде
считать ещё не реализованными.

**Публичная поверхность продукта**

- **API показа карточки** — кому видно эту карточку / это поле.
- **Права на карточке** — кто может действовать с этой карточкой.

Авторизация показа и действий — **по карточке**. Теги — способ сменить
права сразу на много карточек, не второй каталог и не workspace.

Четыре класса доступа, названные владельцем: **пользователь**,
**editor**, **admin**, **платный контент-мейкер**. Платный
контент-мейкер — класс контента и прав. Не workspace, не org, не team,
не вторая общая ризома. Одна общая ризома на инсталляцию без изменений.

**Что не снимается сегодня**

- Глобальный RBAC `user < editor < admin` — грубый шлюз админки,
  очереди и учёток, пока нет покарточных проверок. Роли editor/admin
  **не** удаляются.
- Differ остаётся write gate в **опубликованную общую**, пока отдельное
  решение не скажет иначе. Покарточные права решают, кто может
  предложить, кто решить / принять, кто видеть.
- **Один** Obsidian-плагин (ТЗ **3.26**, снимает 3.09). Очередь из API —
  capability editor’а в том же клиенте; без editor-доступа UI очереди
  выкл. Позже тот же плагин показывает/прячет возможности по грантам
  API на карточке (стык с 3.24). Два каталога в дереве — leftover,
  не канон ([functional.md](functional.md) §6.6.6).
- Закрытый / платный срез ADR-016 и вид «ризома автора» остаются;
  как они стыкуются с покарточным ACL — открытый вопрос.
- Не возвращать исторический `take-from-shared` всего корпуса. ТЗ **3.25**
  сужает 3.22: канон общей остаётся у GraphNotes; editor может держать
  синхронизированную локальную копию **принятых** карточек и открывать
  их из vault. Редактор Markdown на сайте не включать (2.93).

**Открытые вопросы (ответы не выдумывать, матрицу ACL не сочинять)**
