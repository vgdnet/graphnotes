## 5.6. Стартовая страница и модель доступа

Холст ризомы — **`/graph`** (fCoSE). По умолчанию на нём **граф ризомы**
(ТЗ **3.00**). Вкладки «Мой граф» и адреса `/my_graph` **нет**; старый
`#/my_graph` открывает `/graph`. Стартовая **карточка** — **`/card`**, её
выбирает admin в настройках инсталляции (не папка слоя). Граф **не** снимается:
оба адреса канон (ТЗ 2.58). Гость видит узлы опубликованной общей на `/graph` и **открывает карточку**
опубликованной общей: клик по узлу, `[[wikilink]]` и хит поиска ведут на
`/card/{путь}` с Markdown и локальным графом сбоку. Если граф или API не
ответили, гость всё равно видит **название ризомы**, две фразы о ней и
«не удалось загрузить» — не чёрный пустой экран (ТЗ **3.36**). Индикатор
в шапке зелёный только когда процесс **и** данные отвечают; иначе «данные
не загрузились» / «нет связи». Перебор корпуса
гостем режется **после прода** (§16 / ТЗ 2.80), не на тесте. Висячая ссылка: гость
видит «карточки пока нет»; вошедший может создать личную (ТЗ 2.66). Локальный
граф этой заглушки показывает **входящие** связи с живых карточек, не
«граф пока пуст», если кто-то уже ссылается сюда. Личное,
очередь и комментарии — после входа. См. [search-and-card.md](search-and-card.md).

**Вывод:** лендинг **`/`** владелец не переопределил. Пока «старт = граф»
значит `/` → `/graph`. Если `/` должна открывать стартовую карточку — отдельное
слово владельца.

После входа человек попадает на **`/graph`**, не на настройки: git и договор — на
**`/user`** ([user-settings.md](user-settings.md); имя в шапке ведёт туда).
5xx на `/api/users/me` — «связь потеряна», сессию не сбрасывают; 401 — гость.

Права на запись по-прежнему проверяет backend по UUID и назначениям. Вид
графа — не граница безопасности (§3.5). **ТЗ 3.30:** авторизация
карточки — грант `(user_id, card_path)` **или** `(user_id, tag)` **или**
`(user_id, path_prefix)` на запрос, не документ ACL в markdown и не
«учётка editor’а = ризома». Выданная карточка — **один серверный файл**
(право на общий объект); vault на диске — клиентская копия.

### 5.6.1. Роли — не уровни доступа

Иерархия **ролей** остаётся `user < editor < admin` (назначает только
`admin`). Это **грубый шлюз** админки, очереди и учёток. Показ и
действия с карточкой идут через **грант** на путь, тег или префикс
папки (§5.6.7 / ТЗ **3.30** сужает 3.24), не только эту лестницу.
**Уровни доступа к ризоме**
(ADR-016) — не отдельный логин. Это фильтр закрытого среза одной
ризомы. Как он стыкуется с грантом — открытый вопрос, ответы не
выдумывать.

Владелец назвал четыре **класса доступа**: пользователь, editor, admin,
**платный контент-мейкер**. Платный контент-мейкер — класс контента и
прав, не workspace / org / team и не вторая общая ризома. Чем он
отличается от `user` и от `editor`, и станет ли четвёртой RBAC-ролью
(поправка или замена ADR-007) — открытый вопрос.

| Что есть | Что это |
| --- | --- |
| Гость | Нет сессии. Публичный уровень: граф и **карточки** опубликованной общей |
| Сессия `user` / `editor` / `admin` | Роль RBAC. Карточки **опубликованного** уровня; Differ/предложение по правилам §5.4 |
| Автор | Статус договора на том же UUID. Может держать **закрытый срез** в своём git |
| **Платный уровень доступа** | Закрытая часть контента. Тело видно только с этим уровнем (автор среза, UUID с entitlement, `admin`). Не роль «потребитель» |
| Editor | Роль. Очередь в **опубликованную** общую. Закрытый срез **не** модерирует. Набор редакционных прав — грант пути / тега / префикса папки (§5.6.5) |
| Admin | Роль. Видит закрытые срезы как admin, не «оплатил за всех» |

Обычный авторизованный без уровня на чужой закрытый срез видит замок, не
тело (§5.4.1), пока `admin` (или позже оплата) не выдаст уровень.

### 5.6.2. Что видно на графе

Один граф, разный **фильтр по уровню доступа**. Вид холста (теги, сироты,
группы, стрелки, силы — ТЗ **3.39**) гость и сессия крутят одинаково:
это не граница доступа.

- **Гость** — только опубликованная общая. Без чужого и своего личного overlay,
  без закрытых узлов. Карточку общей открывает (клик по узлу / ссылка).
- **Авторизованный** — опубликованная общая + **свой** личный слой на графе:
  из git, если подключён; иначе из серверного хранилища. В меню слоя два
  имени, не «ваш git»: **«ваша часть ризомы»** — пересечение с общей
  (текущий overlay: личные заметки, которые сами ссылаются на видимую
  страницу общей), не весь личный склад; **«ваша личная ризома»** — полный
  проиндексированный личный граф. Слои считает индекс автоматически:
  человек не составляет вручную, какие заметки — «часть», какие — личная
  ризома. Карточки и база изменений (лента / Graph Diff) читают ту же
  видимость, не второй каталог. Чужой закрытый срез — нет, пока нет
  **уровня доступа** к нему.
- **Автор** — как авторизованный, плюс **свой** закрытый срез (не вторая
  ризома, не второй git-репозиторий знаний). Свой срез можно смотреть
  фильтром на `/graph` или видом «ризома автора» (§5.6.4).
- **Есть уровень доступа к чужому закрытому срезу** — как авторизованный,
  плюс вид «ризома автора»: граф и карточки этого среза (§5.6.4). Это
  метка entitlement на UUID, не роль.
- **Editor** — как авторизованный (и свой закрытый срез, если автор). Очередь
  — отдельно. Чужой закрытый срез не открывается и не ревьюится без уровня
  или без `admin`.
- **Admin** — опубликованное + закрытые срезы (видеть и открывать карточки).
  Не заменяет выдачу уровня остальным.

Закрытый / платный уровень **не** предложение в общую и **не** работа
editor’а. Шлюз оплаты — отдельное решение: он только **выдаёт уровень**.
Хранение — §5.4.1 и ADR-016: тот же личный склад (у нас XOR git), маркировка
путей, не второй knowledge repository.

### 5.6.4. «Два графа» и вид «ризома автора»

Согласовано с продуктологом (2026-09-04): «два графа» в письме владельца —
это **не** две базы и **не** вторая общая ризома.

- **Общая ризома** — карта на `/graph`. Git → индекс → граф, карточки, поиск,
  очередь. Авторы предлагают через Differ; editor принимает → commit в общий
  git → пересборка. Editor может ещё писать в этот же общий git напрямую
  (аудируемый commit), не вторым складом.
- **Свой слой** у вошедшего уже есть (Stage 6): общая плюс **своя** ризома
  (overlay / «ваша часть ризомы» / «ваша личная ризома»). На экране это
  **один граф с фильтром слоя**, не два отдельных мира.
- **Закрытый / платный срез** живёт в том же личном хранилище (git XOR
  файлы у нас), с маркировкой путей. Не второй knowledge repository.

После **уровня доступа** к закрытому срезу человек открывает **вид**
«ризома автора»: граф и карточки только помеченных закрытых путей. Это
экран/фильтр той же модели, не вторая сущность, не клон и не ZIP.

«Загрузить» в этом контуре — **открыть вид в GraphNotes** после entitlement.
Не скачать файлы в vault / Obsidian покупателя и не отдать закрытый корпус
продуктовым ZIP/clone.

Платный продукт — только помеченный срез. Весь личный склад (черновики,
кандидаты Differ) покупателю не отдаём.

Публичный поиск и комментарии живут на **опубликованной общей** (и на своём
слое себе). Чужой открытый личный репозиторий как витрина «все ищут,
находят и комментируют» **не принят**: это обошло бы очередь editor’ов и
§3.3. Открытый вопрос — §12 п. 9.

### 5.6.5. Грант записи: путь, тег, префикс папки (ТЗ 3.21 / **3.30**)

Роль по-прежнему `editor` (назначает `admin`). Четвёртой роли, workspace
и второго каталога тегов нет.

**Где живут права.** Гранты — строки в БД GraphNotes **общей ризомы**
(`access_grants`: `user_id`, `kind`, `value`), не во frontmatter, не ACL
в markdown, не «на учётке как ризома». Одна общая ризома на инсталляцию
— **отдельно от любой учётки**, включая editor. ТЗ 3.24 «права живут на
карточке» сужен (§5.6.7): авторизация — грант, не blob ACL внутри
markdown.

Admin выдаёт **право записи** в трёх формах (один примитив):

1. `(user_id, card_path)` — этому UUID эта карточка (`kind=path`);
2. `(user_id, tag)` — этому UUID группа карточек с этим тегом
   (`kind=tag`; тот же тег, что в поиске и в Markdown);
3. `(user_id, path_prefix)` — этому UUID все опубликованные карточки,
   чей путь лежит **под** префиксом папки (`kind=prefix`, например
   `психология/`). Естественная группировка, когда тегов нет.

**Не** добавлять workspace / org / team. **OPEN (позже):** грант по
исходному автору карточки.

**Проверка на запросе.** GET / PUT / очередь / sync **этого пути**:
write, если есть прямой грант пути **или** хотя бы один тег карточки
совпал с tag-грантом **или** путь начинается с выданного префикса
папки. Список / очередь / файл / sync — одна функция. Нет гранта —
карточка **не грузится** в этот срез (403/404), не только прячется в
UI.

Тот же примитив можно выдать любому `user` на 1–10 карточек (или на
папку / тег): срез editor’а и «несколько карточек участнику» — **один**
механизм, не два продукта.

**Редакционный набор (роль `editor`).** Видеть карточку в `/queue` и в
Card Merge, принять / отклонить / вернуть / откатить, Save & Resolve —
только на опубликованную общую **и только если на этой карточке есть
editor-capability** (грант + грубый шлюз очереди). Закрытый / платный
срез по-прежнему не очередь editor’а (ADR-016). Не выдумывать ACL
«читать абзац / прятать тело».

Выдаёт **только `admin`** (editor не выдаёт). UI: **Администрирование →
Доступы** — четыре способа, не четвёртая роль (**ТЗ 3.33** — поиск,
не один выпадающий список на весь корпус):

- по пользователю: поиск по нику → список учёток; у выбранной сразу
  видны права (роль, автор, активность, гранты) → добавить / снять;
- по карточке: поиск по пути / заголовку → **список карточек** (без тел)
  → выбрать путь → видеть / добавить пользователей;
- по тегу: поиск → **список тегов**; клик по тегу показывает гранты
  и карточки с этим тегом (пути / заголовки, без тел);
- по папке (префиксу): поиск / ввод префикса → список папок → выдать.

`PATCH /api/admin/users/{id}/editor-tags` остаётся узким шлюзом
tag-грантов (заменяет все `kind=tag` этой учётки). Пустой список тегов
больше не «вся очередь».

**Смена ТЗ 3.21 (явно, с 3.28; 3.30 не возвращает).** Нет гранта (ни
пути, ни тега, ни префикса) = **нет дополнительной записи в общую**,
не весь корпус и не вся очередь. Empty **не** clone ризомы. Роль
`editor` — грубый шлюз UI очереди (`can_see_queue`); **содержимое**
очереди и запись в общую — только выданный срез. `admin` видит и решает
все карточки очереди (bypass), но пустой грант **не** выгружает ему весь
корпус в vault.

**Что даёт write-grant (матрицу CRUD не выдумывать).** Write = load
среза в vault (клиентская копия) **и** sync обратно в **тот же**
серверный файл общей. Публичное чтение опубликованной общей гостем —
не этот грант. **OPEN:** отдельный грант «только читать» для ревью
очереди. Пока не сказано иначе — очередь и решения только по карточкам
с write-grant. Read-for-queue-only на файлах выданной или открытой
заявки допустим, если без него ревью очереди невозможно; это не общий
read-без-write.

**Поток после выдачи.** Грант выдан → карточка **уже** тот общий файл,
который ему можно писать (`shared_notes`; не копировать в
`personal_uploads`) → плагин **скачивает** её в vault (клиентская
копия; локальное побеждает, ТЗ 2.91) → если локальный ≠ серверный файл,
sync в **тот же** серверный файл → если на этой карточке
editor-capability: очередь чужих правок → принять: сначала локально
(ТЗ 3.25 операция 1) → если локальный ≠ серверный, sync в тот же файл.
Личный склад на сервере держит **только невыданные черновики**.

**Тот же грант, user с 1–10 карточками.** Тот же один серверный файл +
копия в vault. Очередь — только если на этих карточках есть
editor-capability.

**Отзыв гранта.** Write / sync / load-update этого файла с API
прекращаются. Копия в vault **может остаться** на диске; с API её
больше не загружают и не обновляют.

**Снято.** Формулы «три копии (vault + личный склад + общая), потом
схлопнуть»; «write-grant = load среза в личное + sync обратно» (черновик
3.28 / 3.29); «учётка editor’а и есть ризома» (3.27); «права живут на
карточке» как primary (3.24). «Позже vault на диске = ризома» —
**не канон**: диск остаётся клиентом. Исторический `take-from-shared`
корпуса, редактор сайта (2.93) и вторая ризома не возвращаем.

**Долг runtime.** Код ещё может держать **две таблицы** на один путь
выданной карточки (`personal_uploads` и `shared_notes`). Это
недописанный код, не второй канон (ТЗ 3.05). Канон реализации: грант
как право на `shared_notes`, не копия в личное.

- Есть гранты — очередь, тела файлов очереди и решения **только** по
  выданным карточкам. Нет гранта на путь → карточка **не загружается**
  (404/403). Файлы той же заявки вне гранта остаются в очереди для
  другого editor’а / `admin` (как одна карточка в ТЗ 3.18).
- `admin` видит и решает все карточки очереди, гранты его не режут.
- У `editor` без грантов очередь (сайт `/queue` и плагин) показывает
  явное пустое состояние «Нет грантов», не «нет предложений».
- Свой договор и авторский Differ грантами editor’а не режутся.
- Без write-гранта участник по-прежнему предлагает через Differ /
  очередь (ТЗ 3.27 `can_propose_to_rhizome` — сегодня user-only для
  **невыданных** карточек). Свой договор сам по себе в общую не пишет.

Это не уровень доступа к закрытому срезу и не «платный тег». Тег и
префикс папки — способы задать грант сразу на много карточек, не
витрина гостю. Гость по-прежнему читает опубликованную общую на сайте.

### 5.6.6. Личное = черновики; выданная карточка — один серверный файл (ТЗ 3.22 / **3.25** / **3.26** / **3.27** / **3.30**)

«Editor должен иметь доступ к общему» не значит, что общее хранилище
**подменяет** ему личное или что vault editor’а становится **второй
канонической** общей ризомой. И не значит, что **учётка editor’а и есть
ризома** — эта формула 3.27 **снята**.

У каждого (`user` / `editor` / `admin`) **своё** личное хранилище —
свой UUID, свой vault, свой `personal_uploads`. В личном складе на
сервере — **только невыданные черновики**. Чужое личное недоступно.

**Общее** хранилище одно на инсталляцию (`shared_notes`, опубликованная
ризома) и **живёт на GraphNotes, отдельно от любой учётки**. Доступ к
нему — грант, не «роль editor = весь корпус». Выданная карточка — **один
серверный файл**; грант — право на этот объект, не второй blob в
личном складе.

Vault Obsidian — **всегда клиентская копия**. Плагин при открытии /
sync скачивает выданные карточки; локальное побеждает; если локальный ≠
серверный — sync в **тот же** серверный файл. После принятия из очереди
сначала пишет локально (ТЗ 3.25), затем sync в тот же файл, если
локальный ≠ сервер.

- **читать** опубликованные карточки на сайте (граф, `/card`, поиск) —
  витрина гостя/сессии, не dump корпуса в vault;
- **принимать правки от других участников** — сайт `/queue` или плагин,
  **в пределах гранта** (§5.6.5): принятие **только через editor’а**
  и только если на этой карточке editor-capability;
- **после принятия файла** (ТЗ **3.25**) — **две отдельные операции**,
  не одно «Save & Resolve = POST в общую»:
  1. всегда записать принятый файл в **локальный vault**; открытие
     карточки — эта локальная заметка; если запись не удалась —
     принятие не закончено;
  2. только если локальный файл ≠ **тот же** серверный файл ризомы —
     sync в этот файл **от аккаунта с грантом**; если совпадают —
     вторую операцию пропускают. Differ / очередь — write path в общую
     для людей **без** write-grant (участники);
- **не** выгружать всю ризому ZIP/clone в vault (ТЗ 2.5);
- **не** делать vault второй канонической общей и **не** считать
  «позже диск vault = ризома» каноном.

**ТЗ 3.25 сужает 3.22 и остаётся.** Card Merge — очередь правок **от
других участников**. Принятие **через editor’а**. После принятия файла —
**две отдельные операции** (локальная запись всегда; sync в один
серверный файл только если локальный ≠ склад). Runtime пишет vault
первым; POST `/resolve` не блокирует локальную запись. Канон
опубликованной общей — GraphNotes. Vault — клиентская копия, не вторая
ризома. Открытие карточки после принятия — локальная заметка
(обязательный UX).

**Один** плагин (ТЗ **3.26** снимает 3.09), один токен `gnp_`. Очередь
— capability того же клиента: показывают при открытии Obsidian, **если
у учётки editor-доступ на эту карточку**; иначе UI очереди выкл.
`can_propose_to_rhizome` остаётся user-only (ТЗ **3.27**) для
**невыданных** карточек. Каталоги `obsidian-plugin/` и
`obsidian-card-merge/` — leftover runtime; склейку кода в этой волне
не делать, если ещё не сделана:

```text
невыданный черновик:  vault  ↔  personal_uploads  (личное)
выданная карточка:    vault  (клиент)  ↔  один shared_notes файл
                      очередь чужих — если editor на этой карточке
участник без гранта:  Differ / proposals → очередь → тот же shared файл
```

Card Merge **не** описывать как «только кэш `.obsidian`, никогда
заметка vault». Кэш `.obsidian/plugins/…/work/` остаётся черновиком
сравнения; **принятая** карточка — обычная заметка vault по пути
карточки.

**Два и больше editor’ов** уже сейчас в модели: одна очередь, одно
общее, у каждого своё личное (черновики) и грант на те же общие файлы.
Принимают **параллельно разные** карточки. Одну и ту же карточку в
работу берёт **один** человек; второй видит, что она занята (серверный
слот — если локальный ТЗ 3.16 не виден другим). Гранты (§5.6.5) режут,
кто какие карточки видит. Своё предложение принять нельзя.

После принятия каждого файла — **две операции** (ТЗ **3.25**): сначала
обычная заметка vault по пути карточки (без этой записи принятие не
закончено); потом, **только если** локальный файл ≠ один серверный
файл ризомы, sync в этот файл. Runtime пишет vault первым; POST
`/resolve` не блокирует локальную запись.
Editor открывает **локальную** заметку новым листом не-MergeView
(`createLeafBySplit` / `getLeaf(true)`; шаги — `debug.log` плагина)
(ТЗ 3.17 / **3.19** / **3.25**). Очередь справа остаётся сбоку.
Исторический `take-from-shared` корпуса и редактор сайта (2.93) не
возвращаем.

**ТЗ 3.27 — грубый флаг офера, не вечный ACL.** Сегодня:
`GET /capabilities` `can_propose_to_rhizome` — `true` у глобальной роли
`user`, `false` у `editor` и `admin`. Card Merge прячет **весь**
Differ-офер и не вызывает GET `/differ` / POST `/proposals` этой панели.
Сайт `#/differ` «в ризому» с этой роли тоже скрыт. POST `/proposals` при
`false` — 403. Очередь (`can_see_queue`) не зависит от флага офера.
Флаг остаётся user-only для **невыданных** карточек.

Не читать 3.27 как «editor никогда не предлагает, навсегда» и не как
«учётка editor’а и есть ризома». Канон объекта — грант на путь / тег /
префикс: предложить / писать в общую / модерировать очередь. Платный
контент-мейкер — по-прежнему открытый вопрос.

**Дыры / правила (не выбирать молча опасный вариант; ACL не выдумывать)**

1. **Editor среза vs editor-автор других карточек — OPEN.** Один человек
   может быть editor на теге A и автором карточки B вне write-гранта.
   Сегодня `can_propose_to_rhizome=false` на всю учётку editor’а. Если он
   должен предлагать B как автор — слово владельца; пока офер editor’а
   выкл.
2. **Личное vs общее.** Sync публикатора — vault ↔ личные **невыданные**
   черновики. В общую с учётки — только карточки с write-grant (тот же
   серверный файл) / принятые из очереди, **не** каждый личный черновик.
   Не проводнить «sync всех файлов vault в shared».
3. **Запись без второго человека.** Правка по write-гранту в общую **не**
   пункт очереди. Очередь — правки **других**. Granted sync — PUT
   выданного файла в `shared_notes`; POST `/resolve` остаётся для
   принятия чужой заявки.
4. **Не тот API.** Не использовать POST `/proposals` (офер `user`) как
   вторую операцию editor’а и не как granted write. Эндпоинты офера
   остаются для `user` без write-гранта.
5. **Admin** сегодня как editor (тот же hide офера). Платный мейкер —
   OPEN.
6. **Долг runtime: две таблицы.** `personal_uploads` + `shared_notes`
   на один путь выданной карточки — leftover против «один серверный
   файл». Не второй канон.
7. **Отзыв гранта.** Stop write/sync/load-update с API. Копия в vault
   может остаться; не выдумывать автоудаление.

### 5.6.7. Покарточный API и грант (ТЗ 3.24, сужен ТЗ **3.30**)

Владелец (2026-09-16) уточнил модель. Вопрос «Тогда API получается
покарточное?»:

- **Эндпоинты — по карточке:** GET/PUT **этот** путь (показать /
  загрузить / синхронизировать эту карточку).
- **Авторизация — грант** в БД: `(user_id, card_path)` **или**
  `(user_id, tag)` **или** `(user_id, path_prefix)`, считается **на
  каждый запрос**. Write, если прямой путь **или** любой тег карточки
  совпал **или** путь под выданным префиксом. Write-grant = право на
  **один серверный файл** общей, не второй blob в markdown и не
  ACL-документ в файле. **OPEN:** read-без-write для ревью очереди;
  грант по исходному автору.
- **Не** «покарточный ACL на заметке». Документ ACL в markdown **не**
  хранят.
- ТЗ **3.24** «права живут на карточке» **сужен**: это не primary.
  Primary — грант в БД, оценка по пути.

**Один механизм, не два продукта.** Editor среза получает грант на
уже существующий общий файл; плагин скачивает в vault; дальше очередь
(если editor-capability) + правки **того же** файла. Тем же примитивом
любому `user` выдают 1–10 карточек, тег или папку: тот же один серверный
файл + копия в vault; очередь — только если на этих карточках есть
editor-capability.

**Поверхность API.** Список, очередь, файл, sync — одна функция гранта.
Нет гранта → карточка **не грузится** (404/403), не только спрятана в
UI. Гость по-прежнему читает опубликованную общую на сайте (граф /
`/card`) — витрина, не editorial grant. Сегодняшний `GET /api/cards/{path}`
для публичной общей — не этот грант.

Четыре класса доступа без изменений: **пользователь**, **editor**,
**admin**, **платный контент-мейкер** (класс контента/прав, не workspace
и не вторая ризома).

**Что не снимается сегодня**

- Глобальный RBAC `user < editor < admin` — грубый шлюз админки,
  очереди и учёток. Роли editor/admin **не** удаляются. Выдача грантов
  — **admin-only**.
- Differ остаётся write gate в опубликованную общую для людей **без**
  write-grant (`user` предлагает). Granted write = sync vault → **тот
  же** серверный файл (`shared_notes`).
- **Один** Obsidian-плагин (ТЗ **3.26**, снимает 3.09). Очередь из API —
  capability editor’а в том же клиенте. Два каталога — leftover; склейку
  кода в этой волне не делать, если ещё не сделана.
- Закрытый / платный срез ADR-016 остаётся; стык с грантом — открытый
  вопрос.
- Не возвращать исторический `take-from-shared` всего корпуса. ТЗ
  **3.25** для принятых файлов очереди без изменений. Редактор сайта
  не включать (2.93). Диск vault = ризома — не канон.

**Открытые вопросы (ответы не выдумывать, матрицу ACL не сочинять)**

1. Точные глаголы: видеть / предложить / решить / принять входящее /
   прятать тело. ТЗ **3.27** сегодня режет «предложить» грубым флагом
   роли. Write уже назван: load + sync в один shared файл.
2. Чем платный контент-мейкер отличается от `user` и от `editor`.
3. Закрытый срез ризомы (ADR-016) vs грант.
4. ADR-007: поправка или замена. **Нужен ADR:** один плагин снимает
   3.09; грант API (3.30 сужает 3.24; один серверный файл; три kind).
   Редактор продуктового ТЗ ADR не пишет.
5. Две таблицы на один выданный путь (`personal_uploads` +
   `shared_notes`) — leftover против канона одного файла.
6. **OPEN:** грант по исходному автору карточки.
7. **OPEN:** read-без-write для ревью очереди (кроме read-for-queue-only
   на файлах выданной или открытой заявки).

Ранний контекст 3.23 (карточка с правками у автора заявки — он следит
в БД и принимает входящее в плагине; иначе срез ризомы editor’у)
остаётся **намеченным клиентским контуром** под грантом, не развилкой
«выбрать A или B».
