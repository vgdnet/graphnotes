## 2. Видение продукта

GraphNotes — слой общей ризомы над Markdown в Git, а не второй Obsidian.
Люди пишут заметки в своём vault (часто Obsidian + obsidian-git или аналог).
GraphNotes показывает одну общую ризому графом и даёт группе editor’ов
собрать её из того, что Differ нашёл у человека в **его** личном хранилище
(git **или** загрузки файлов — не оба сразу) и чего ещё нет (или что отличается)
в общей. Опубликованную
общую **нельзя скачать** файлами из GraphNotes: нет ZIP, нет кнопки «Скачать»,
нет продуктового clone корпуса. Чтение — в приложении. **Стартовая страница — граф общей ризомы**, в том
числе без входа: гость видит только публичный граф и **не** открывает
карточки ([access.md](access.md) §5.6).

Круговорот Markdown:

```text
написал в git XOR загрузил .md
  -> Differ нашёл отличия к общей ризоме
      -> предложил выбранное
          -> очередь editor’ов
              -> приняли в общую
                  -> Differ снова сравнил
                      -> отличий нет
                          -> авторский вклад в общей остаётся
```

Обратного пути «забрать общую файлами» нет: ни ZIP, ни clone как
продуктовый сценарий. Личный git остаётся у человека; общая читается
в GraphNotes.

Ценность первой версии — живой граф, Differ и человеческая очередь слияния, а
не клон редактора заметок и не обёртка над GitHub PR.

Следующая волна после успешной первой версии: **человек на общей ризоме**.
GraphNotes помнит не только текущий граф, но **историю взаимодействия с общей
ризомой**: кто создал карточку, кто поправил текст, кто поставил связь
(прочитал две карточки и соединил их). У автора и у editor есть **карточка
пользователя** — публичный след вклада, не GitHub-профиль.

Differ остаётся единственным путём личного → общее. Несколько editor’ов
разбирают много предложений; решение всегда за человеком. Подсказки
(в том числе будущая нейросеть) не принимают в общую сами.

Текст версий заметки живёт в Git общей ризомы. GraphNotes не дублирует тела
заметок ради «истории правок». Статистика и лента «кто что сделал с общей»
живут в продукте, потому что из git log это не прочитать: коммит делает
приложение, а не UUID автора.

См. ADR-008, ADR-009; на provenance, ленту взаимодействий и карточку
пользователя нужен ADR.

Инсталляция на **rhizome.vsepsy.ru** соседствует с базой психологов
**vsepsy.ru**: тот же человек входит той же почтой и паролем, каталог
специалистов в ризому не сливается (§6.1.3).
