## 4. Термины

| Термин | Определение |
| --- | --- |
| Заметка | Markdown-файл и его индексированное представление |
| Узел | Производное представление заметки или unresolved-ссылки в графе |
| Связь | Производное направленное отношение между заметками из Markdown-ссылки |
| Личная база | Локальный склад GraphNotes. Пишет **плагин** (ТЗ **3.35**). Git copy-in и загрузки `.md`/ZIP с сайта — leftover (2.96). Храним последние 30 версий файла для отката; индекс / граф / Differ — только последняя. |
| Индекс | Производные строки в PostgreSQL (`note_index` и связи) для поиска и графа. Не канон текста (ТЗ 2.63) |
| Тестовый граф | Вкладка `#/graph-test` (ТЗ **3.41** / **3.43**): проба холста Pixi.js + d3-force на том же индексе, что «Граф». Та же шестерёнка; узлы по кругу. Не канон ризомы и не второй API |
| Выгрузка своей | Если есть — файлы с локального склада этого UUID. Не синтез из индекса. Общую так не отдают |
| Общая ризома | Единственное утвержденное коллективное Markdown-состояние одной инсталляции и его производный граф. Рабочая копия **у нас** (`shared_notes`) |
| Differ | Сверка двух складов (личное ↔ опубликованная общая). Исходящее — предложить выбранные пути в ризому (ТЗ 3.11). Входящее — новые правки в карточках, которые автор уже отдавал, и принять их в своё хранилище (ТЗ 3.13). Не merge-редактор. Вкладка `#/differ` |
| Авторский вклад | Заметки и связи, которые этот пользователь написал или ввёл: ещё только в личном складе, предложенные через Differ, принятые в общую |
| Provenance | Производная атрибуция узла или связи: автор (UUID GraphNotes), слой, revision, связь с предложением при наличии |
| Взаимодействие с общей | Событие на опубликованной общей ризоме: создана карточка, изменён текст, создана или снята связь, предложение рассмотрено. Не git log и не снимок текущего графа |
| Карточка пользователя | Сущность `#/users/{login}` (ADR-012 / ТЗ 2.95 / **2.97** / **2.98**, §5.4.3). Канон — логин (`#/users/efimov`); path `/users/{login}` открывает ту же карточку, не граф. Публичный UUID в адресе и в JSON карточки запрещён. Видна гостю и вошедшему. Описание (имя, роль, открытые контакты); кто пригласил; статистика вклада; число карточек и связей в личном складе; число карточек и связей, предложенных в ризому; объём предложенных правок (Б/КБ/МБ). Тела чужих личных файлов и закрытый срез не входят. «Мой вклад» — `/contribution` |
| Настройки | Экран учётки на `/user`: четыре вкладки — личные данные, договор автора, токен плагина Obsidian, **«Пригласить пользователя»** (отправка инвайт-письма, ТЗ 2.85–2.86; не в «Личных данных»). Вкладки «Свой git» нет (ТЗ **3.38**). Почта обязательна; телефон и Telegram по желанию; уведомления очереди и одна галочка/ползунок «Получать уведомления об изменениях в карточках, которые вы правили» (ТЗ 3.15). Имя в шапке открывает этот адрес. Не граф и не админка |
| Гость | Нет сессии: публичный холст `/graph`, поиск, **карточки опубликованной общей** и **карточка человека** `#/users/{login}` (§5.6, §6.5.2, ТЗ 2.95 / **2.97**) |
| Карточка ризомы | Узел ризомы. Клик по узлу и `[[wikilink]]` открывают `/card/{путь}`: Markdown и локальный граф сбоку. `/card` без пути — стартовая карточка из настроек admin (404 если не задана). На сайте файл не правят (ТЗ 2.93). История правок — по кнопке, последние 30 редакций: кто **предложил** правку, diff, объём (ТЗ 2.94 / **3.34**). Гость читает опубликованную общую и её редакции. Висячая ссылка: гость видит «карточки пока нет»; вошедший может создать личную карточку с этой страницы или из плашки при наведении на ссылку |
| Поиск карточек | Поле на `/graph` (подсветка) и экран `/search` (каталог). Хит вошедшего — `/card/{путь}`. Ищет только видимый этому зрителю слой |
| VsePsy | Соседний продукт — база психологов на https://vsepsy.ru/. Не ризома |
| Связанная учётка vsepsy | Почта+пароль с vsepsy.ru открывают rhizome.vsepsy.ru без второй регистрации; роли каталога не копируются (§6.1.3) |
| Ачивка ризомы | Opt-in публичный кусок вклада (граф и/или счётчики) для vsepsy.ru и своего сайта; не ZIP; поля карточки всему интернету не зафиксированы (§6.1.4) |
| Уровень доступа к ризоме | Фильтр видимости среза одной ризомы: опубликованное / свой закрытый / чужой закрытый при entitlement. Не RBAC-роль (ADR-016) |
| Платный уровень доступа | Закрытый срез контента: тело видно автору, UUID с этим уровнем и `admin`; иначе замок. Шлюз оплаты только выдаёт уровень, не второе хранилище. Стыковка с грантом — открытый вопрос (ТЗ 3.29) |
| Платный контент-мейкер | Класс доступа / прав (ТЗ 3.24 / 3.29): контент и показ, не workspace и не вторая ризома. Чем отличается от `user` и `editor` — открытый вопрос |
| Покарточный API | Эндпоинты GET/PUT **этого** пути (ТЗ **3.30**). Авторизация грантом path/tag/prefix, не ACL-документ в markdown. Сегодняшний `GET /api/cards/{path}` публичной общей — витрина, не грант |
| Грант | Строка в БД общей: `(user_id, card_path)` или `(user_id, tag)` или `(user_id, path_prefix)`; write на запросе GET/PUT/очередь/sync пути, если прямой путь **или** тег карточки совпал **или** путь под префиксом папки (ТЗ 3.21 / **3.30**). Срез editor’а и user с N карточками — один механизм. Не «права живут на карточке» (3.24 сужен). Write-grant = право на **один серверный файл** общей, не второй blob в личном складе. Личное — невыданные черновики. Vault — клиентская копия. Очередь чужих — только с editor-capability |
| Права editor’а по тегам | Редакционный грант (`/queue`, Card Merge) на карточки с выданными тегами. **Смена 3.21:** пустой список ≠ вся очередь; нет гранта = нет дополнительной записи в общую (ТЗ **3.30** / §5.6.5) |
| Ризома автора | Вид закрытого среза после уровня доступа: граф и карточки только помеченных путей. Не вторая ризома, не второй git и не весь личный склад автора (§5.6.4) |
| Загрузить (закрытый срез) | Открыть вид «ризома автора» в GraphNotes после entitlement. Не скачать `.md` в vault / Obsidian и не ZIP/clone корпуса |
| Серверное личное хранилище | **Единственный** рабочий склад `.md` на стороне GraphNotes. Пишет плагин (ТЗ **3.35**). На `/graph`: **«ваша часть ризомы»** и **«ваша личная ризома»** — фильтры, не вкладка «Мой граф» (ТЗ 3.00). Для **выданной** карточки канон — файл общей, не второй blob здесь; leftover runtime может ещё держать копию в `personal_uploads` |
| Серверное хранилище общей | Рабочая копия опубликованной ризомы на инсталляции (`shared_notes`). Карточки и индекс читают этот склад |
| Ваша часть ризомы | Overlay / пересечение: видимая общая страница плюс только те личные заметки, которые сами ссылаются на неё. Не весь личный склад. Слой считает индекс, не ручной список |
| Ваша личная ризома | Полный проиндексированный личный граф (`GET /api/graph/personal`) из локального склада. Карточки и поиск на этом слое — из этого дерева, не высыпание vault на общий граф |
| Загрузка без git | Leftover ТЗ 2.96: с сайта кнопок нет. Когда вернётся — API синхронизирует `.md`/ZIP в локальный склад, как плагин. Не второй канон |
| Токен интеграции | Простой личный ключ API `gnp_…` для плагина (ТЗ 2.76): кабинет `/user` → Obsidian хранит и снова показывает ключ, чтобы скопировать позже. Плагин помнит тот же ключ в `data.json`. Отзыв блокирует ключ; новый ключ снова из кабинета. Не SSH-ключ и не «секрет один раз». История входов на `/user` ~6 месяцев (ТЗ 2.73–2.74). Scopes только личного склада. Пароль учётки в плагин не входит |
| Передача из плагина | Копирование локального vault → личное хранилище этого UUID (ТЗ 2.68–2.90 / §6.3.4). Очередь локально; сеть — кнопка «Передать правки на сервер» в боковой панели / лента / закрыл файл / минуты, не каждый символ. Первая заливка — «Отправить все правки». После копии боковая панель может предложить исходящий Differ в очередь (ТЗ 3.20). Не запись в общую |
| GraphNotes Publisher | Бесплатная часть публикатора в **одном** Obsidian-плагине (ТЗ **3.26**): desktop-клиент и API, чтобы человек разместил **свой локальный граф** в личном складе инсталляции. Не тариф Obsidian Publish, не официальный продукт Obsidian и не запись в общую. Очередь editor’а — capability того же пакета, не второй `.zip` |
| GraphNotes Card Merge | Leftover-имя второго desktop-пакета (`obsidian-card-merge/`, ТЗ 3.09 **снят** ТЗ **3.26**). Канон — один плагин: очередь правок от других через editor’а — capability того же клиента (UI при открытии Obsidian, если есть editor-доступ). После принятия — две операции (3.25). Не ZIP общей и не вторая каноническая ризома. Два каталога в дереве — leftover, пока один пакет не поставлен |
| Локальная копия принятой карточки | Обычная заметка в vault editor’а после принятия (ТЗ 3.25, операция 1, всегда) (клиентская копия того же серверного файла, ТЗ **3.29**). Не вторая каноническая общая: канон — один файл ризомы. Editor открывает карточку из этого локального хранилища. Если запись не удалась — принятие не закончено |
| Один Obsidian-плагин | Канон ТЗ **3.26** (снимает 3.09; 3.23 было только направление): один клиент. Почему — проще; позже тот же плагин показывает/прячет возможности по гранту API, когда доступ **не ко всем карточкам, а только к выданным** (стык с 3.29). Очередь из API — capability editor’а. Ручная правка — тот же sync. Код двух пакетов — leftover. Не `take-from-shared` (§6.6.6, §5.6.7) |
| Просьба ризомы | То, что Differ уже нашёл: личная карточка без пары в опубликованной общей — «дай её нам, если хочешь». Сначала кабинет на сайте; в плагин — следующая итерация (ТЗ 2.88). Не принятие и не публикация |
| Предложенная тема | Приглашение на сайте написать новую карточку в **личное** (дыра общей, висячая ссылка, пробел слоя). Не готовая карточка в общей (§6.6.3) |
| История загрузок | Продуктовая лента: кто, когда, какие файлы, хеш содержимого, результат Differ/предложения. Не git log |
| Предложение | Заявка из выбранных результатов Differ в общую ризому, очередь editor’ов. Текст для принятия — таблица Википедии / wikidiff2 (ТЗ 3.03). Git-backed merge — leftover ТЗ **3.35** |
| Graph diff | Структурный вид Differ/предложения: добавленные, удаленные или измененные узлы и связи |
| Unresolved link | Ссылка на заметку, которой еще нет в выбранном состоянии |
| Антипарсинг чтения | После прода: режет гостевой перебор опубликованных карточек (один адрес → много путей). Не закрывает чтение общей и не капча на карточку (§16 / ТЗ 2.80) |
| Инвайт | Письмо со ссылкой-приглашением (ТЗ 2.86 / §17). Без него учётки нет; окна «Регистрация» нет. Выдаёт любой с учёткой. Цепочка кто кого позвал. Та же модель на vsepsy.ru |
