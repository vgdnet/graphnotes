## 6.1.3. Учётка с vsepsy.ru (тот же домен)

Эта инсталляция GraphNotes живёт на **https://rhizome.vsepsy.ru/**.
База психологов — соседний продукт на **https://vsepsy.ru/**, не вторая
ризома и не витрина карточек специалистов внутри GraphNotes.

Один человек на семействе доменов `vsepsy.ru` не заводит вторую почту и
второй пароль, чтобы читать и вести вклад в ризоме.

Канон продуктового ТЗ базы: `vsepsy/docs/PRODUCT_TZ.md` §11.16. Если тексты
разъедутся — править оба.

### Что человек делает

- На vsepsy.ru (кабинет психолога `/pro` или иной экран со ссылкой) видит
  переход **в ризому** — открывается rhizome.vsepsy.ru.
- На ризоме входит **той же почтой и тем же паролем**, что на базе.
  Повторно регистрировать этот адрес нельзя: это уже его учётка.
- После входа это обычный GraphNotes `user` на внутреннем UUID: граф,
  настройки, Differ, договор автора — по правилам ризомы, не кабинета
  психолога.
- Гость по-прежнему видит только публичный граф без карточек (§5.6).

### Что общее, что нет

| Общее | Не общее |
| --- | --- |
| Почта + пароль (вход на оба сайта) | Роли: админ/модератор vsepsy **не** становятся `admin`/`editor` ризомы |
| Человек узнаёт себя (связь учёток) | Карточка психолога, заявки, тесты, журнал поисков |
| Смена пароля действует на оба входа | Блокировка в каталоге ≠ блокировка в ризоме (пока admin того продукта не заблокирует там) |
| Ссылка «ризома» / «база психологов» | Тела заметок, git, очередь editor’ов, `/ops` Starlette-Admin |

Регистрация на ризоме с улицы (логин/пароль GraphNotes) остаётся **до**
волны инвайтов (ТЗ 2.84 / §17). После неё улица без инвайта не
регистрируется. Если почта уже есть на vsepsy.ru **и** учётка ризомы
уже связана — это вход, не новая регистрация. Первое появление с
vsepsy без инвайта — открытый вопрос §17.3, не молчаливый аккаунт.

### Кого переносим, кого нет

- **Да:** учётка vsepsy.ru с **почтой и паролем**. Основной сценарий —
  психолог. Пациент с почтой и паролем может войти в ризому так же, как
  `user`; карточки пациентов, тесты и поиски **не** едут с ним.
- **Нет:** анонимный хеш-аккаунт бота поиска. Это не вход в ризому.
- **Нет:** только Telegram без почты и пароля. Сначала на vsepsy.ru
  привязывает почту и задаёт пароль, потом ризома. Telegram **не** identity
  provider GraphNotes (ADR-002).

Первый вход на ризому этими данными создаёт или привязывает UUID GraphNotes.
Вторая учётка с той же почтой не появляется.

### Пароль

- Открытый пароль не хранится и не пишется в журнал ни в одном из продуктов.
- Admin ризомы может задать новый пароль (§5.3.1) — после этого вход **и**
  на vsepsy.ru, **и** на ризоме этим новым паролем. Иначе «тот же пароль»
  ломается.
- Задать пароль на стороне базы (если вход там ещё только кодом на почту) —
  требование ТЗ vsepsy §11.16, иначе мигрировать нечего.

### Чего этот пункт не делает

- не сливает каталог психологов с общей ризомой Markdown;
- не делает маркетплейс b17 внутри GraphNotes;
- не обещает «вошёл на vsepsy.ru — сессия уже открыта на ризоме» (общая
  cookie на `.vsepsy.ru` — отдельное решение, не этот текст);
- не переносит `/ops` и справочники vsepsy в вкладку «Администрирование».

Это меняет границу идентичности (ADR-002): нужен ADR, затем `MASTER_CONTEXT`.
До ADR в код как новая архитектура не идёт.

### 6.1.4. Ачивка ризомы: граф, счётчики, данные «для моего сайта»

Автор может **показать миру след вклада в ризоме** — как ачивку, не как
выгрузку корпуса.

Это не каталог психологов и не ZIP общей ризомы. Это узкий публичный кусок:
то, что человек **сам включил** для показа на vsepsy.ru, на своей карточке
автора и (по желанию) на **своём сайте**.

**Что умеем показывать (форма, не финальный набор цифр):**

- фрагмент **графа** вклада (узлы/связи принятого в общую, без закрытого
  корпуса и без тел чужих заметок);
- **количество** (например заметок, принятых в общую, связей — состав
  счётчиков не зафиксирован);
- другой **параметр вклада**, когда владелец продукта его назовёт.

Точный список полей карточки автора и карточки психолога, которые можно
выставить **всему интернету**, **не принят**. Вернёмся к обсуждению.
До решения в публичный API не кладём ничего, кроме того, что автор явно
включил из уже разрешённого узкого набора. По умолчанию ачивка **выключена**.

**Куда это едет**

| Куда | Как |
| --- | --- |
| vsepsy.ru, карточка психолога | Кусок API ризомы: «данные для витрины / ачивка». База не считает заметки сама |
| Свой сайт человека | Тот же публичный кусок («данные для моего сайта»): вставка или вызов API |
| Карточка автора в GraphNotes | Тот же выбранный показ, если включён |

**Жёстко нельзя в ачивке / публичном куске:** закрытый и платный корпус;
тела заметок как файл/ZIP; очередь editor’ов; журнал поисков и заявки
vsepsy; почта, телефон, пароль; чужой личный git.

Включение и выбор «что светить» — в **Настройках** ризомы, не на графе.
Снять показ можно в любой момент: внешние вставки перестают получать данные.

Гость уже открывает опубликованную общую в GraphNotes (ТЗ 2.64). Нужен ADR,
если публичный кусок **выносит тела наружу** (embed/ZIP) или меняет закрытый
срез. До решения по полям — только каркас.
