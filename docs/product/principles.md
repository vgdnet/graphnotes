## 3. Неподвижные продуктовые принципы

### 3.1. Markdown - источник истины

Каноническое знание хранится в **Markdown**. Узлы, связи, теги, поисковый
индекс и визуальный граф — производные.

```text
.md → копия в локальный склад GraphNotes (загрузка / коннектор / плагин Obsidian)
  -> parser
      -> PostgreSQL index
          -> Graph API
              -> Web UI
```

Рабочая копия Markdown — **всегда** склад инсталляции GraphNotes: личный
слой и опубликованная общая (ТЗ 2.63). GitHub, git, позже Dropbox / Google
Drive — коннекторы: они **копируют** файлы сюда, не подменяют склад.
Поисковый индекс той же природы: сейчас в PostgreSQL `note_index` (SQL).
Следующая итерация — Elasticsearch (ADR-015 / ТЗ 2.83): начинается
**только после первой утверждённой выкатки на production `rhizome`**.
Не второй канон Markdown и не «положить тела в индекс, чтобы поиск был
быстрее». Выгрузка своей части — с локального склада `.md`, не сборка из
индекса.

Запрещено вводить параллельный канонический `graph.json`. Слиянию и
версионированию подлежит Markdown; после изменения склада граф
переиндексируется.

### 3.2. Личный и общественный слои

- в одной инсталляции существует ровно одна общая ризома;
- у каждого пользователя **ровно одно** личное рабочее хранилище: локальный
  склад GraphNotes. Внешний диск (git / позже Dropbox / Google Drive) не
  второй канон: продукт копирует `.md` в этот склад (§6.3 / ТЗ 2.62–2.63);
  **по умолчанию человек работает у нас**, коннектор не обязателен;
- личный слой — Markdown в этом единственном хранилище; холст один —
  `/graph` (по умолчанию ризома; ТЗ 3.00);
- общий слой — утверждённое коллективное знание **одной** ризомы, только в
  приложении, с правами (ADR-007, §5.6);
- личный граф — проекция личного слоя плюс связи с общей; не отдельный файл;
- общественный граф — проекция утвержденного Markdown общей ризомы;
- сравнение слоёв — **Differ**: односторонние отличия **локального** личного
  склада к опубликованной общей (ADR-009). Коннектор только обновляет копию
  у нас; Differ не ходит «в Dropbox» и не считает git вторым складом.

Общая читается в приложении. Личное — **копия у нас**, с какого бы диска её
ни принесли. Workspace, organization, team, community и несколько общих ризом
не входят в текущую модель.

Каноническая формула: **«Личное — локальный склад GraphNotes (внешние диски
только копируют `.md` сюда); у каждого свой граф; единая общая ризома —
проверенное коллективное знание с правами, как Publish плюс очередь
editor’ов».**

### 3.3. Автор — единица вклада

- автор в продукте — внутренний UUID GraphNotes, не GitHub-login как
  пользовательская идентичность;
- человек пишет во внешнем vault; на склад пишет **плагин** (загрузки с
  сайта нет, ТЗ 2.96); тонкий
  in-app редактор на сайте **выключен**, пока нет обратной выгрузки (ТЗ 2.93).
  Плагин/API или коннектор копирует `.md` на склад (вход локального графа —
  бесплатно, ТЗ 2.82); разговор «что отдать в общую» — на сайте ризомы, не
  публикация из Obsidian;
  GraphNotes не становится журналом набора текста; тела **опубликованной
  общей** не копируют в PostgreSQL в обход Differ;
- продукт обязан сохранять и показывать **авторский вклад**: какие заметки
  человек написал, какие связи ввёл, в каком состоянии они сейчас
  (только личное / предложено / принято в общую);
- после принятия вклад не исчезает вместе с Differ: он остаётся в общей ризоме
  с provenance автора **и** в ленте взаимодействий с общей;
- создать связь в общей = зафиксировать, **кто** соединил две карточки;
  это статистика человека, не побочный эффект парсера;
- чужой личный склад не показывается как «ризома другого автора» всем подряд;
  на общей видны принятые заметки и связи и, когда известно, кто их внёс;
- вид «ризома автора» после уровня доступа — только **помеченный закрытый
  срез**, не весь чужой личный слой и не вторая общая (§5.6.4). Открытый
  чужой личный как публичная витрина (искать и комментировать всем) не
  принят, пока нет отдельного решения владельца и ADR.

### 3.4. GitHub не склад пользователя

GitHub **не** хранилище знания (ТЗ 2.61–2.63). Продукт — хостинг графа и
карточек на инсталляции (как Obsidian Publish), со своими правами.

GitHub остаётся: (а) доставка **исходников GraphNotes** (`nord → GitHub →
rhizome-test → rhizome`, ADR-006); (б) **необязательный** личный git как
коннектор, который копирует `.md` в локальный склад (ТЗ 2.62); (в) источник
опубликованной общей: копирует `.md` в локальный склад общей (ТЗ 2.63).
Merge через GitHub App после accept editor’а — leftover, не UX. Обычный
пользователь работает с «личная ризома», «мой граф», «общая ризома», «отличия»,
«предложить в общую», «принять / отклонить / откатить», «автор», «мой вклад»
и «карточка человека», а не с branch, SHA и Pull Request. **Стартовая страница — граф общей ризомы**
(и без входа). Форма «владелец/имя репозитория» не первый экран: свой git
подключают в **Настройках**, если человек этого хочет
([user-settings.md](user-settings.md) §5.5). Кто какой слой графа и карточки
видит — [access.md](access.md) §5.6.

### 3.5. Граф не является границей безопасности

Разделение веток или визуальных слоев само по себе не обеспечивает изоляцию.
Права проверяются backend на основании внутреннего UUID пользователя и
глобальной роли. Credentials GitHub App пользователям не выдаются.

Действия записи через приложение (загрузить, править свою карточку,
предложить из Differ, editor) требуют аккаунта. Гость на стартовом графе
открывает **опубликованную общую** карточку (§5.6 / ТЗ 2.64). GraphNotes
**не отдаёт** опубликованную общую файлами (нет ZIP «Скачать», нет clone
корпуса как UX). Чтение общей — граф и карточки в приложении. Credentials
GitHub App пользователям не выдаются.
